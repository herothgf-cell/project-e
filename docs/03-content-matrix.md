# 콘텐츠 제작 범위와 의존 관계

- 버전/작성일: v0.1 / 2026-10-21
- 상태: 초기 제작량과 출시 후보 범위의 제안. 실제 제작 완료 목록이 아니다.
- 관련: [로드맵](02-development-roadmap.md), [캐릭터 공통](characters/README.md), [표현](content/01-world-and-presentation.md), [모드/UI](content/04-modes-onboarding-and-ui.md)

## 1. 콘텐츠 확장의 원칙

먼저 영웅 1명으로 전투를 검증하고, 다음에는 영웅 3명과 맵 1개로 실제 3대3 한 판을 만든다. 여섯 영웅 후보는 M3에서 재미·상대법·읽기 쉬움을 확인한 뒤 한 명씩 추가한다.

이 문서는 **무엇을 얼마나 만들지** 관리한다. 공통 판정과 숫자는 [공통 규칙](01-core-rules.md), 좌표는 [M01](content/02-arena-and-objectives.md), 개별 기술은 영웅 문서를 따른다.

## 2. 단계별 제작량

| 요소 | M1 진단 | M2 한 판 | M3 알파 | M4–M5 출시 후보 |
|---|---|---|---|---|
| 플레이 영웅 | C01 1종 | C01–C03 3종 | 3종 검증·표현 개선 | 검증을 통과한 C01–C06 6종 후보 |
| 패시브+액티브 정의 | 5개 | 15개 | 같은 15개 수정 | 30개 후보, 영웅별 1패시브+4액티브 |
| 주력 맵 | 전투 진단 구역 | M01 1개 | 같은 맵의 시야·동선 조정 | 같은 맵 1개 완성 |
| 병력 유형 | 필요할 때 더미 | 근접·원거리·공성 3종 | 경로/표적 개선 | 3종 완성 표현 |
| 경험치 셀 | 보상 더미 | 1유형, 맵에 6개 | 위험/보상 조정 | 같은 유형 유지 |
| 방어 시설 | 판정 더미 | 외곽/내곽 탑 총 12개, 핵 2개 | 경고·보호 표시 개선 | 같은 구조 완성 |
| 상점과 소비품 | 수치 진단 UI | 양 팀 상점 2곳, I01/I02 2종 | 구매·복귀 선택 검증 | 필요성 입증 시에만 확대 재기획 |
| 경기 내 성장 | 진단 투자 UI | 6선택 범주, 레벨 1–12 | 선택 이유·가독성 개선 | 같은 핵심 체계 완성 |
| 봇 | 전투 더미/제어 시험 | 기본 라인 봇·접속 손실 대체 | 연습과 학습 검증 | 출시 범위의 난이도와 표시 완성 |
| 온라인 | 2클라이언트 진단 | 비공개 실제 3v3 | 6인 비공개 알파 | Steam 비공개 방, 공개 큐는 조건부 |
| 학습/메뉴 | 조작 안내 | 선택·준비·HUD·결과 | 단계별 훈련/튜토리얼 | 지원 언어·설정·오류 안내 검수 |

위의 5/15/30개는 패시브와 액티브의 기획 단위 수다. 하나의 기술에 여러 피해 단계나 이펙트가 있어도 기술 수를 부풀리지 않는다. 탑 12개는 같은 유형 자산을 재사용할 수 있는 배치 수이며 고유 모델 12종을 뜻하지 않는다.

## 3. 최초 영웅별 제작 목적

| ID | 영웅 | 테스트할 고유한 조작·판단 | 필요 선행 요소 | 상세 기획 |
|---|---|---|---|---|
| C01 | 바스 | 짧은 진입 이후 지연 공격을 맞히고 안전하게 빠져나오는 판단 | 이동·근접 판정·보호막·강제 제어 | [바스](characters/01-bas.md) |
| C02 | 리오 | 자신의 이동으로 투사체 귀환 경로를 만들고 회수 시점을 활용 | 투사체 단계·이동·궤적 표시 | [리오](characters/02-rio.md) |
| C03 | 네마 | 제한된 장치의 위치·연결선과 파괴 위험으로 통로를 관리 | 소유 장치·수명·설치 제한·시야 | [네마](characters/03-nema.md) |
| C04–C06 | 후속 후보 | 기존 영웅의 의무 조합 없이 새로운 진입/지원/교전 선택 추가 | M3의 조합·학습·판정 데이터 | [확장 후보](characters/04-roster-expansion.md) |

각 영웅은 기본 조작만 바꾼 수치 변형으로 만들지 않는다. 조작하는 사람이 다른 결정을 내리고 상대도 다른 방식으로 대응해야 한다. 기획에서 상대법을 적을 수 없는 기술은 제작에 넘기기 전에 수정한다.

## 5. 모드·학습·UI

| 묶음 | 필요한 흐름 | 첫 포함 단계 | 출시 후보의 완료 조건 |
|---|---|---|---|
| 훈련 | 영웅 선택, 더미, 자원/성장 초기화, 기술 설명 | M1 진단 → M3 학습 | 원작 지식 없이 조작과 대응을 연습 가능 |
| 튜토리얼 | 이동 → 공격/회피 → 성장 → 지원 → 공성 | M3 | 건너뛰기·재시도·입력 변경을 지원 |
| 봇 연습 | 인원 구성, 봇 표시, 한 판, 결과 | M2 | 정보 치팅 없이 유효한 연습 제공 |
| 비공개 방 | 생성·초대·참가·팀/영웅·준비·시작 | M2, Steam 경로 M4 | 실패/이탈/버전 차이/복귀를 설명 |
| 경기 HUD | HP·에너지·기술·소비품·성장·미니맵·공성 상태 | M1–M2 | 중요한 경고를 가리지 않고 읽힘 |
| 결과 | 승패·세션 중단·피해·공성·성장·재경기 | M2 | 킬 수 이외의 기여와 실패 이유를 전달 |
| 설정 | 입력, 화면, 소리, 색상 외 표식, 언어 | M1부터 단계 적용 | 저장/복원·키 충돌·해상도별 검수 |
| 공개 큐 | 찾기·취소·경기 성립·연결 실패 | M4에서 제공 여부 판단 | 실제 수요와 지역 품질의 근거 확보 |

공개 큐가 없어도 훈련·봇·비공개 방은 하나의 제품 흐름으로 이어져야 한다. 테스트 참가를 위해 사용자에게 Unity 에디터 설치를 요구하는 방식은 외부 배포의 완료 조건으로 인정하지 않는다.

## 6. 아트·애니메이션·효과·오디오 산출물

### 영웅 한 종의 제작 묶음

- 실루엣과 재질 기준, 게임 카메라에서 구분되는 3D 모델/리그.
- 대기·이동·기본 공격·피격·사망과 기술에 필요한 동작. 공통 리그를 재사용하더라도 기술 위험과 타이밍이 달라야 한다.
- 패시브/Q/W/E/R의 아이콘, 사거리/범위 표시, 선딜 경고, 발사/적중/종료 효과.
- 기술 시작·적중·중요 상태·사망의 사운드. 시야 밖 정보 전달 정책을 적용한다.
- 선택 화면·HUD·미니맵의 식별 표시와 초보자용 한 문장 설명.
- 적/아군 구별, 낮은 그래픽 설정, 색상 인지 차이, 다수 기술 중첩에서의 확인 기록.

임시 자산 → 판정이 일치하는 전투 표현 → 최종 모델/음원 순서로 승격한다. 기술 타이밍이 바뀔 때마다 최종 애니메이션을 재제작하는 일을 줄이기 위해 M1–M2에서는 실루엣과 경고를 우선한다.

### 공통 제작 묶음

| 분야 | 수량을 관리하는 단위 | 범위 관리 방법 |
|---|---|---|
| 맵 | M01 한 개의 모듈·바닥·차폐·기지 세트 | 교전 가독성을 해치는 소품과 복잡한 지형 제거 |
| 병력 | 3유형, 양 팀 구분 변형 | 팀별로 완전히 별도 리그를 만들지 않아도 됨 |
| 구조물 | 외곽/내곽/핵의 3기능군 | 잠금·병력 보호·노출·파괴 상태를 표현 |
| 셀/소비품 | 셀 1유형, 소비품 2종 | 상태·사용 가능 여부가 작은 UI에서도 구분 |
| UI | 공통 버튼/패널/툴팁/경고/미니맵 체계 | 영웅별 임의 UI 규칙을 최소화 |
| 음악·환경음 | 메뉴·경기·결과의 기능 구분 | 전투 경고의 명료도를 우선하고 곡 수는 예산 후 확정 |
| 스토어 | 제목·캡슐·아이콘·실제 화면·영상 | M3 이후 실제 제품 표현을 사용 |

아트 원본의 구체적인 개수·해상도·리그 사양은 실제 아티스트와 제작 도구가 정해지면 이 묶음 안에서 산정한다. 임의의 숫자를 완성 일정의 근거로 쓰지 않는다.

## 7. 콘텐츠 상태 관리

콘텐츠의 상태는 `기획 → 임시 구현 → 규칙 검증 → 사람 플레이 검증 → 표현 완료 → 출시 검수`로 기록한다. 모델이 완성되었다고 기술 판정과 온라인 검증까지 완료로 처리하지 않는다.

작업 카드에는 요소 ID/이름, 담당 역할, 해당 단계, 의존 작업, 기획 링크, 검증 빌드, 완료 증거를 적는다. 별도 작업 관리 서비스를 사용하는 경우에도 최종 규칙은 저장소 문서와 데이터에 남긴다.

## 8. 우선순위와 보류 범위

| 우선순위 | 포함 대상 | 판단 |
|---|---|---|
| 핵심 | 이동·기술·성장·라인·지원·공성·온라인 신뢰 | M1–M3에서 우선 검증 |
| 제품 완성 | 튜토리얼·봇·설정·설치/업데이트·가독성·오류 안내 | 외부 테스트와 출시 전에 완성 |
| 검증 후 확장 | C04–C06, 공개 매칭, 소비품 외 구매 선택 | 데이터가 필요성을 보일 때 착수 |
| 초기 보류 | 두 번째 맵, 랭크, 배틀패스, 계정 능력치, 외형 상점, 캠페인, 다른 플랫폼 | 핵심 제품 이후 별도 기획 |

추가 영웅 수만 늘려 대응 가능한 조합을 만든다는 접근은 피한다. 특정 조합이 필수라면 기존 영웅과 공통 규칙에서 선택이 막힌 원인을 먼저 확인한다.

## 9. 변경 시 함께 갱신할 문서

- 영웅 수·모드·플랫폼 변경: 개요, 로드맵, 이 매트릭스, Steam 제품 설명.
- 공통 피해/자원/성장 변경: 공통 규칙, 해당 영웅 예시, 경제 예시, 플레이테스트 기준.
- 이동/사거리/맵 변경: 맵 좌표·지원 시간, 캐릭터 상대법, 봇 이동, 시야 검사.
- 영웅 기술 변경: 개별 영웅, 애니메이션/효과/소리 작업, 튜토리얼, 온라인 재현 사례.
- 출시 범위 축소: 플레이 가능한 선택 다양성, 사용자 설명, 운영 가능성을 다시 확인.
