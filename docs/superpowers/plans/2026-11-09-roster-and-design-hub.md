# V8 콘텐츠 기획 허브와 8인 로스터 구현 계획

사용자가 요청한 콘텐츠별 상세 기획, 시티 오브 템페스트 역기획, 다양한 캐릭터 8명 프로토타입을 기존 Godot 프로젝트에 연결한다. 현재 기준 소스는 V7 main `0296818189782b3d9620e149eb8dd17d0d745294`이다. 문서 목적지는 기존 작업 기준을 따라 GitHub `doc/design`의 게임허브로 해석했다. 캐릭터 규모는 기존 3명을 포함한 총 8명으로 해석했다.

## 설계 결정

- 선택 풀은 바스, 리오, 네마, 오린, 테르, 무아, 세라, 루메 8명이다. 경기는 각 팀 3명으로 구성한다.
- 기존 후보 오린의 발사 준비, 테르의 후퇴 보호, 무아의 활성 구역을 판타지 테마에 연결한다. 세라는 표식 근접 암살, 루메는 지연 화염 포격을 맡는다.
- 8명 모두 기본공격, 패시브, QWER, 성장, 소모품, 봇 행동, F7 연출실에서 실제 실행 가능해야 한다.
- 신규 수치는 V8 실험값으로 기록한다. 원작 수치의 확인 범위와 버전 차이는 역기획서에 출처와 함께 기록한다.
- 현행 전투의 30Hz 판정, 벽과 시야, 중복 적중 방지, CC 상한, 구조물 보호를 공용 경로로 적용한다.
- 문서는 게임허브 목차, 현재 게임 콘텐츠 상세, 원작 역기획, 영웅 시트, 실행 검증으로 연결한다. 현재 동작과 후속 실험의 상태를 각 문서에 표시한다.

## 검토 항목

1. 8명 선택이 경기 인원을 늘리거나 팀 내부 중복, 비어 있는 라인을 만들지 않는가.
2. 새 스킬이 표시만 바뀌고 실제 효과가 빠진 상태로 성공하지 않는가.
3. 다회 타격은 고유 단계로 각각 한 번 처리하며 사망과 취소 뒤 잔여 예약이 규칙대로 정리되는가.
4. 무아 구역과 세라 표식이 벽·안개를 통해 숨겨진 정보를 노출하지 않는가.
5. 960×540에서도 8명 선택과 경기 시작 버튼이 겹치지 않는가.

## 검증 명령

```bash
python3 tools/check_godot.py --godot /absolute/path/to/Godot_v4.7.2-stable_linux.x86_64
python3 tools/check_art_assets.py
python3 tools/check_audio_assets.py
python3 -m unittest discover -s tools/tests -p 'test_package_windows.py'
```

새 기능의 실제 효과 검사와 기존 전체 회귀를 모두 완료 기준으로 사용한다. 실제 렌더와 Windows 실행, 수동 다인 플레이는 수행한 범위대로 검증 기록에 기입한다.
