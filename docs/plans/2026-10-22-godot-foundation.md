# Godot 개발 기반과 첫 조작 진단 장면

- 작성: 2026-10-22, Asia/Seoul.
- 근거: 사용자가 Godot 진행을 선택했다. 기존 [개요](../00-project-brief.md), [공통 규칙](../01-core-rules.md), [바스](../characters/01-bas.md)를 따른다.
- 범위: 엔진 전환 문서, 실행 가능한 M0 기본 프로젝트, 오프라인 이동/E 진단. 전체 M0 또는 M1 완료 보고가 아니다.

## 설계

Godot **4.7.2 Standard**, 타입을 명시하는 GDScript, Compatibility 렌더러로 시작한다. 프로젝트는 `game/project-e/project.godot`, 첫 제품 대상은 Windows x86_64다. 이번 실행 검증 환경은 Linux x86_64이며 Windows 검증과 구분한다.

작은 평면 장면에서 우클릭 이동, S 정지, E 후 좌클릭 방향 확정, Esc 조준 취소, F2 초기화를 제공한다. 바스의 이동 속도 5.8m/s와 E의 선딜 0.12초·속도 14m/s·최대 거리 4.2m·후딜 0.16초·에너지 20·쿨다운 5초를 사용한다. 에너지는 최대 100, 초당 8 회복한다. 벽을 넘지 않는다. 시전 승인 시 방향·비용·쿨다운을 확정한다.

E의 영웅 충돌 피해·밀치기·CC, Q/W/R, 기본 공격, 성장, 봇, 미니언, M01, 온라인 전송은 다음 단계다. 단순 충돌 진단 장면에는 경로 탐색과 행동 예약이 없으며 벽 반대편 클릭은 자동 우회를 제공하지 않는다. HUD는 조작과 현재 에너지·쿨다운·동작 상태를 보여 준다. 임시 도형은 아트 컨셉 확정을 의미하지 않는다.

`BasMotion`은 입력·명시적 시간으로 이동 의도와 E의 상태를 계산하는 `RefCounted`다. `ProbePlayer`가 `CharacterBody3D` 충돌을 적용한다. `CombatProbe`가 입력과 HUD를 담당하며 전투 규칙에 Steam·UI 객체를 넣지 않는다. 이 분리는 온라인 입력 검증 경계의 출발점이며 서버 권위·예측이 구현됐다는 뜻은 아니다.

**Architecture:** 시간·이동 규칙, 3D 충돌, 입력·화면을 세 파일로 분리한다. 입력값의 유효성 및 E의 승인 시 비용을 규칙 계층에서 검사한다.

**Tech Stack:** Godot 4.7.2 Standard / GDScript / Compatibility / GodotPhysics3D / 물리 tick 30Hz.

## 검토할 실패 조건

1. 같은 위치·NaN 조준으로 에너지나 쿨다운이 소비되지 않아야 한다.
2. 선딜·돌진·후딜 중 재시전이 들어와도 비용이 중복 소비되지 않아야 한다.
3. 큰 한 프레임의 시간에도 돌진 거리가 4.2m를 넘지 않아야 한다.
4. 실제 벽에서 이동 캡슐이 관통하지 않아야 한다.
5. 초기화 후 목표점·조준·에너지·쿨다운이 이전 플레이 상태를 남기지 않아야 한다.
