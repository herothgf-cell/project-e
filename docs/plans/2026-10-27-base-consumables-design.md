## 목적과 범위

경기에서 이미 얻는 크레딧을 기지 구매와 라인에서의 회복 선택으로 연결한다. 이번 묶음은 R09 전체(권한 판정, 재고·선택·사용, 상점과 HUD, 안내)와 R10 중 소모품 구매/사용 판단만 포함한다. 핵 방어·지원·라인 전환, 설정 저장, 온라인, 전체 전투 동작·음향은 별도 남은 작업이다. Windows 실행 파일은 새 소스로 다시 내보내며 실제 Windows PC/사람 플레이는 수행 증거 없이 완료 처리하지 않는다.

## 접근 방식과 개발 판단

1. 기존 경기 상태 파일에 구매·사용·지속 회복을 모두 넣는 방식은 시작이 간단하지만 이미 큰 전투 파일에 상품과 오류 처리가 섞인다.
2. **작은 `battle_consumables.gd`를 두고 경기 상태의 명령·타이머·피해·사망 경계에 연결한다.** UI와 봇은 같은 권한 API를 호출한다. 이 방식을 개발 판단으로 선택한다.
3. 별도 범용 아이템/장비 시스템은 현재 두 소모품에 불필요하므로 만들지 않는다.

Godot 4.7.2 Standard/GDScript, Compatibility와 30Hz 권한 판정을 유지한다. 임시 표현과 한국어 글꼴을 재사용한다. 신규 외부 의존성이나 계정/장비 재화를 추가하지 않는다.

## 고정 규칙

| 항목 | 계약 |
|---|---|
| I01 에너지 병 | 40크레딧, 2초 동안 에너지40; 기본 회복과 합산 |
| I02 수리 패치 | 50크레딧, 4초 동안 HP200; 유효한 적 영웅 귀속 피해로 남은 회복 취소 |
| 보유/사용 | 두 종류 합산2개, 사용 시 공통12초 쿨타임 시작 |
| 구매 | 경기 중 살아 있는 영웅이 자기 기지 회복 구역 안에 있을 때만; 돈·재고 한도 재검사 |
| 구매와 전투 | 기지 자연 회복의 전투 이탈 대기시간은 구매 제한으로 사용하지 않는다. 사용 쿨타임 중에도 구매 가능 |
| 사용 | 살아 있고 선택 재고가 있으며 쿨타임이 끝났고 해당 자원이 최대 미만일 때. 부족한 양이40/200보다 작아도 사용 가능; 초과 회복은 버림 |
| 행동 유지 | 이동·공격·시전·예약 명령을 취소하지 않는다. 기절/속박 자체는 소모품 사용이나 진행 중 회복을 막지 않는다 |
| 중단 | 적 영웅의 직접/장치/지속 피해는 패치 중단. 보호막으로 흡수한 유효 피해도 중단. 무효/중복/무적 피해, 제어만 적용, 일반 병력·탑 피해는 중단하지 않음 |
| 사망/부활 | 진행 효과 종료, 남은 재고·선택 유지, 사용 쿨타임은 사망 중 감소; 부활로 쿨타임 초기화하지 않음 |
| 재시작/종료 | 새 경기에서 재고·효과·쿨타임 초기화. 종료 후 구매/사용 불가, 시간 진행 없음 |

회복은 기존 타이머/기본 회복 단계에 적용한다. 같은 틱의 이후 공격이 패치를 끊으면 그 틱까지 지급된 회복은 되돌리지 않으며 다음 틱부터 남은 효과가 없다. 새로운 틱 순서나 피해 판정을 만들지 않는다.

## 입력과 화면

- 기존 **G 성장, B 기지로 걷기** 유지. **P 상점**, **D 선택한 소모품 사용**을 추가한다. 고정 키 변경은 개발 판단이며 키 재지정은 R08이다.
- 두 소모품 슬롯 클릭은 선택만 한다. D 또는 사용 버튼이 한 개를 소비한다. 수량0인 종류도 선택 가능하며 자동으로 다른 품목을 소비하지 않는다.
- 하단 기술 HUD 위에 작은 도구 줄을 배치해 크레딧, P 상점, 두 재고, 선택 강조, D 사용·공유 쿨타임·회복 진행을 표시한다. 1280×720과1920×1080에서 확인한다.
- 상점은 기지 밖·사망 중에도 열어 설명을 볼 수 있다. 구매 불가 이유를 표시한다. 상점 중에는 로컬 경기를 멈추고, P/Esc/닫기는 직전 일시정지 상태로 복원한다.
- 성장·도움말·일시정지 메뉴와 상점을 동시에 열지 않는다. 상점 열기는 조준/카메라 드래그를 정리한다. 상점·재고 클릭은 뒤의 전장 명령으로 전달하지 않는다.
- 사용은 조준과 실제 행동을 바꾸지 않는다. 실패는 재고·쿨타임·기존 명령을 보존하고 한국어로 알린다. 구매·사용·패치 중단 알림은 조작 영웅 정보만 보여 준다.
- F1 안내와 실행 문서에 구매→슬롯 선택→D 사용, B 복귀와 P 상점 차이를 추가한다.

## 봇의 최소 경제 판단

봇도 플레이어와 같은 구매·사용 API를 호출한다. 시작과 기지 재방문에서 빈 종류를 먼저 채워 병1개+패치1개를 목표로 한다(패치 우선, 최대2개·크레딧 조건 준수). 기지에서는 무료 회복을 기다리고 소모품을 쓰지 않는다. 기지 밖에서 HP가 최대보다200 이상 부족하고 마지막 적 피해 후2초 이상이면 패치를, 그 외 에너지가40 이상 부족하면 병을 사용한다. 두 조건이 겹치면 패치 우선이다. 이는 첫 구현 휴리스틱이며 밸런스 검증 결과가 아니다. 적의 숨은 상태를 읽지 않으며 구매를 위해 기존 이동을 중지하거나 새로운 복귀 전술을 만들지 않는다. 조작 중인 영웅과 비활성 봇에는 자동 구매/사용을 적용하지 않는다.

## 검증과 완료 판단

실제 권한 코드로 경계(돈/수량/위치/생존/쿨타임/최대 자원), 정확한 시간별 회복, 장치·보호막·중복 피해 중단, 사망·부활·재시작을 검증한다. 실제 장면 입력으로 P/D/슬롯/구매/닫기와 모달·클릭 차단을 확인한다. 봇 소비가 실제 크레딧·재고·자원에 반영되고 사람 입력을 대신하지 않는지 검사한다. 기존 통합 검사와 새 검사, 실제 렌더, 자연 봇 경기, 새 Windows export/ZIP을 기록한다. 자동·Linux 렌더·내보내기와 실제 Windows PC·사람 검증을 구분한다.
