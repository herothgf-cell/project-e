# Steam 출시·검증 계획

- 상태: v0.2 준비 문서, Steam 계정 등록·결제·App 생성·스토어 공개·출시 미실행.
- 문서 개정: 2026-10-22, Asia/Seoul. Steam 공식 출처 최초 확인: 2026-10-21.
- 범위: Windows PC 출시까지의 증거, Steam 제출물, 테스트 운영, 추후 사용자 결정.
- 관련: [로드맵](../02-development-roadmap.md), [콘텐츠 단계](../03-content-matrix.md), [플레이테스트](../04-playtest-and-balance.md), [기술 기반](../technical/01-godot-and-steam.md).

## 1. 목표 제품과 출시 판단

출시 후보는 Windows x86_64의 빠른 3v3 전투, 주력 맵 한 개, 영웅 여섯 명, 훈련·튜토리얼, 봇 연습, 비공개 방이다.
첫 세 영웅을 만드는 단계에서 여섯 명의 구현 완료나 출시일을 약속하지 않는다.
추가 세 영웅의 실제 제작은 M3에서 재미·역할 구분·가독성을 확인한 뒤 시작한다.
공개 매칭은 Playtest의 동시 접속·대기 시간·지역별 접속 품질을 보고 개방 여부를 결정한다.
랭크, 배틀패스, 계정 전투력 성장, 추가 경쟁 모드는 초기 출시 범위에 넣지 않는다.
12~18분 경기와 60fps는 검증 목표이며 아직 제품의 실측 성능이나 보장값이 아니다.
제작 인원·숙련도·주당 투입 시간·예산이 정해지기 전에는 달력상의 개발 기간을 확정하지 않는다.

## 2. M0~M6의 출시 의존성

| 단계 | 준비할 증거 | 다음 단계로 가는 조건 |

| M2 실제 3v3 | 한 맵·세 영웅·웨이브·성장·공성·기본 봇 | 시작부터 코어 파괴까지 완주 |

| M5 출시 후보 | 최종 범위, 성능, Steam 기능, 심사 자료 | 결함·설명·운영 책임·큐 유지 가능성 검증 |
| M6 출시·운영 | 승인된 빌드, 출시 결정, 대응·패치 절차 | 사용자가 승인한 실제 출시 실행 |

Steam 계정·스토어 준비는 M3 이후의 제품 설명과 검증된 영상이 생길 때 구체화한다.
결제일·심사일이 필요하다는 이유로 미완성 제품의 공개 출시일을 먼저 정하지 않는다.

## 3. Steamworks 등록 준비

공식 절차에는 계약·신원 확인과 은행·세금 정보, 제품 등록과 빌드·스토어 설정이 포함된다. [R1]
등록 주체가 개인인지 법인인지 먼저 정하고 법적 이름과 정산 계좌 명의를 맞춘다.
신원·세금·계좌 원본은 저장소에 보관하지 않고 필요한 담당자와 승인 상태만 기록한다.
프로젝트 표시 이름과 공개 게임 이름을 구분한다. `Project E`와 캐릭터 이름은 가칭이다.
공개 이름 확정 전에는 상표·기존 게임과의 혼동 여부를 별도 확인한다.
접속 권한을 역할에 맞춰 부여하고 업로드·스토어 수정·실제 공개의 담당자를 정한다.
이 문서 작성 권한은 Steamworks 계약 체결, 수수료 결제, App 생성 권한으로 확대하지 않는다.

## 4. 수수료와 일정 조건

Steam Direct 수수료는 확인일 기준 신규 앱당 US$100 또는 이에 상당하는 금액이며 지역에 따른 세금이 추가될 수 있다. [R2]
수수료는 환불되는 보증금이 아니며 제품의 Adjusted Gross Revenue가 US$1,000에 도달한 뒤 지급에서 회수되는 조건이다. [R2]
환율·세금·지급 조건은 실제 결제 시 다시 확인하고 개발 총예산과 별도 항목으로 기록한다.
공개 Coming Soon 페이지는 출시 전 최소 2주 노출 조건이 공식 문서에 안내되어 있다. [R1][R3]
**수수료 결제 후 대기기간은 확인일에 공식 페이지 간 불일치가 있다.**
Onboarding 문서는 21일, Steam Direct 소개 페이지는 30일로 표시한다. [R1][R3]
계획에는 최소 30일 여유를 확보하되 이를 확정 법칙으로 단정하지 않고 실제 앱 대시보드·Steam Support로 적용 조건을 확인한다.
이 기간은 품질 검증이나 심사 통과를 대신하지 않으며, 충족했다고 자동 출시되는 것도 아니다.

## 5. 스토어 자료 묶음

| 제출물 | Project E 준비 내용 | 검증 기준 |
| --- | --- | --- |
| 짧은 소개 | 3인 지원·경기 내 성장·공성 결정을 한 문장으로 | 참고 게임 이름에 기대지 않아도 이해 가능 |
| 상세 소개 | 실제 출시 범위, 조작, 모드, 온라인 조건 | 아직 없는 기능을 현재 제공한다고 쓰지 않음 |
| 스크린샷 | 실제 빌드의 전투·지원·공성 장면 | 컨셉 이미지로 플레이 화면을 대체하지 않음 |
| 영상 | 조작, 인접 라인 지원, 성장 선택, 코어 공략 | 편집으로 가린 지연·개발 상태를 제품 기능처럼 오인시키지 않음 |
| 캡슐·아이콘 | 최종 제목, 자체 아트, 작은 크기의 식별성 | Steam의 해당 시점 규격으로 내보내기 |
| 언어 | 한국어 우선, 영어 UI·설명 파이프라인 | 지원 표시한 언어를 실제 빌드와 대조 |
| 시스템 요구 | 시험한 Windows·CPU·GPU·RAM·저장 공간 | 추정 사양을 검증 완료처럼 표시하지 않음 |
| 콘텐츠 설문 | 실제 폭력·통신·온라인 요소 등의 정확한 답변 | 배포 지역과 당시 Steam 요구 사항 확인 |

Steam 심사는 스토어에 표시한 기능의 구현과 지원 OS에서의 실행 등을 확인한다. [R4]
스크린샷은 실제 게임플레이를 사용하고, 향후 기능은 현재 제공 기능과 명확히 구분한다. [R4]
사운드·폰트·모델·텍스처의 출처와 상업 배포 권리를 출시 후보별로 확인한다.
참고 게임의 영웅·지도·이름·UI를 그대로 옮긴 자료는 제작·홍보 자산에 포함하지 않는다.

## 6. 심사와 공개의 순서

스토어와 빌드의 체크리스트를 각각 완료하고 Valve 심사를 요청한다.
공식 절차상 스토어 심사 제출이 빌드 심사 제출보다 먼저다. [R5]
Review Process 문서는 스토어·빌드 심사를 통상 3~5영업일, 계획 여유를 최소 7영업일로 안내한다. [R4]
이는 처리 기한 보장이 아니므로 수정·재제출·휴일을 고려해 공개 날짜를 정한다.
Coming Soon 공개와 게임 출시는 서로 다른 동작이며 승인된 빌드도 스스로 출시되지 않는다. [R5]
실제 공개 전에는 계정에 필요한 권한, 선택 빌드·가격·지원 언어·일정을 다시 대조한다.
스토어 공개·심사 제출·출시 버튼 실행은 이 문서에서 수행하지 않았다.

## 7. 빌드·브랜치 운영 제안

| 경로 | 용도 | 승격 조건 |
| --- | --- | --- |
| 로컬 진단 빌드 | M1 조작·네트워크 원인 분석 | 재현 가능한 실행과 로그 |
| `internal` 브랜치 후보 | 내부 Steam 설치·업데이트 시험 | 정상 시작·종료와 패키지 권한 |
| `closed-alpha` 브랜치 후보 | 제한된 외부 테스트 | 프로토콜·콘텐츠 버전 일치 |
| 별도 Playtest App | M4 모집·지역별 검증 | 참가 안내·운영 시간·회수 계획 |
| `release-candidate` 브랜치 후보 | M5 회귀와 출시 자료 고정 | 알려진 중대 결함 0건 |
| `default` | 최종 승인된 기본 배포 빌드 | 명시적 승격 판단·복구 빌드 준비 |

Steam 브랜치는 공개 또는 비밀번호 제한으로 제공할 수 있으며 기본 브랜치는 일반 사용자가 받는 빌드다. [R6]
브랜치 비밀번호만으로 게임 소유권이 생기지는 않는다. 시험 계정의 package·depot 접근을 함께 확인한다. [R7]
빌드마다 commit, Godot·export template·애드온 버전, Windows x86_64 export 설정, 콘텐츠 hash, 프로토콜, Steam Build ID와 변경 내역을 연결한다.
다른 프로토콜의 사용자는 같은 방에 입장시키지 않고 업데이트 안내를 표시한다.
잘못된 빌드 배포에 대비해 이전 호환 빌드와 설정 복구 방법을 기록한다.
위 브랜치 이름은 제안이며 실제 Steam 브랜치를 생성했다는 의미가 아니다.

## 8. M4 Steam Playtest

Steam Playtest는 본편에 연결된 별도 App ID로 테스트 접근을 관리하는 무료 기능이다. [R8]
간소화된 스토어 자료와 빌드 심사를 거치며 모집 표시는 본편 페이지와 연결된다. [R8]
무료 기능이라는 뜻은 본편 등록, 개발, 서버 운영 비용까지 없다는 뜻이 아니다.
작은 예약 세션부터 시작해 접속 지역과 시간을 모으고 6명을 실제로 채울 수 있는지 검증한다.
참가자에게 테스트 시간, 임시 데이터, 예상 오류, 의견 제출 경로, 종료 시 접근 중단 가능성을 안내한다.
Playtest 접근권을 판매하거나 테스트 안에서 수익화를 진행하지 않는다. [R8]
단순 테스트를 위해 유료 Early Access를 기본 선택으로 두지 않는다. 유료 미완성 판매는 별도 제품 결정이다.
서버 로그와 설문은 가명 세션 식별을 우선하고 수집 항목·보유 기간·담당자를 정의한다.
재화·성장은 경기 내에서만 유효하며 Playtest 참여로 영구 전투력 우위를 주지 않는다.

## 9. 공개 매칭 개방 조건

친구 방이 잘 동작하는지와 낯선 6명이 적정 지연으로 만날 수 있는지를 따로 측정한다.
지역·시간대별 동시 접속, 파티 규모, 대기 p50/p95, 경기 시작 실패율, 중도 이탈을 기록한다.
초기 조사 기준은 예약 시간대에 6인 경기 성립률 90% 이상, 대기 p95 120초 이하로 제안한다.
이는 출시 보증값이 아니라 M4~M5의 운영 판단 가설이며 표본 수·관찰 시간을 함께 공개한다.
소수의 친구·봇으로 채운 결과를 자연 유입 수요나 공개 큐의 유지 가능성으로 계산하지 않는다.
기준 미달이면 테스트 시간대를 집중하거나 비공개 방·봇 연습 중심 출시 범위를 다시 결정한다.
대기를 줄이려고 검증되지 않은 지역을 섞어 전투 지연을 악화시키는 조치는 별도 시험을 거친다.
공개 큐를 약속할지는 이 결과와 운영 예산을 본 뒤 사용자와 결정한다.

## 10. M5 출시 후보 확인

- 6인 전체 경기에서 크래시·진행 불가·중복 보상·복구 불가능한 상태 불일치를 조사하고 중대 결함을 해결한다.
- 검증된 최소 사양에서 1080p·낮음 설정의 프레임 분포와 서버 tick 여유를 기록한다.
- Steam 설치·재설치·업데이트·초대·로비 입장·오버레이·게임 종료를 실제 계정으로 확인한다.
- Steam 또는 네트워크 장애 때 방 입장 실패·재접속·경기 중단 안내가 정확한지 검사한다.
- 키 재지정, 해상도 전환, 오디오, 한국어·영어 문자열, 색상 외의 피격 경고를 확인한다.
- 봇 연습·훈련·비공개 방의 범위와 실제 지원 기능을 스토어 설명에 맞춘다.
- 플랫폼·최소 사양·서버 정책·가격·지원 연락처·개인정보 안내의 책임자를 확인한다.
- 스토어와 빌드 심사 승인, 필요한 대기 조건, 선택한 기본 빌드를 출시 기록에 남긴다.

## 11. M6 출시와 초기 운영

출시 실행 전에 정확한 빌드, 공개 문구, 가격·지역, 시작 시각, 장애 대응 담당자를 검토할 수 있게 묶는다.
사용자가 실제 공개를 승인하면 권한 있는 담당자가 Steam 출시 절차를 실행한다.
첫 운영에서는 로그인·방 입장·경기 완주·크래시·재접속·대기 시간 지표를 함께 확인한다.
신규 콘텐츠보다 접속 불가·경기 중단·판정 불일치 대응을 우선한다.
급한 패치는 작은 변경으로 만들고 같은 결함의 재현 사례·배포 대상·복구 경로를 기록한다.
밸런스 변경은 세 영웅 시절의 인상만으로 판단하지 않고 영웅 조합·실력·파티 조건을 같이 본다.
공개 큐를 잠시 닫거나 예약 세션으로 전환해야 하는 조건과 안내 문구를 미리 준비한다.
초기 반응이 좋다는 이유로 랭크·추가 모드·장기 수익 모델을 즉시 확정하지 않는다.

## 12. 비용·사용자 결정 분리

| 항목 | 지금 할 수 있는 일 | 실행 전에 필요한 결정 |
| --- | --- | --- |
| 문서·기획·로드맵 | 저장소에 검토 가능한 계획 작성 | 현재 요청 범위에 포함 |
| Godot 라이선스·유료 도구 | MIT 고지·애드온/자산 라이선스·후보 비용 정리 | 상업 배포 권리 확인·유료 도구 구매 승인 |
| Steam 등록·수수료 | 입력 자료·절차 준비 | 계약 주체·결제·App 생성 |
| 스토어·Playtest | 문구·자산·테스트 계획 작성 | 공개 이름·게시·모집·접근 허용 |
| 서버 | 후보 구성·부하·견적 비교 | 월 예산·지역·서비스 계약 |
| 가격·출시 | 제품 범위와 실제 준비 증거 정리 | 유료/무료, 가격·지역·출시일·실제 공개 |

Godot은 MIT 라이선스이며 엔진 사용료나 매출 로열티를 예산에 잡지 않는다. 배포 시 필요한 저작권·라이선스 고지는 포함하고, 별도 애드온·모델·음원·폰트와 서버 운영 비용은 따로 확인한다. [Godot License](https://godotengine.org/license/)

서버 예산에는 경기 프로세스, 동시 경기 수, 지역 수, 로그·저장, 모니터링, 트래픽을 포함한다.
Steam 로비와 Relay 제공을 무료 전용 서버 컴퓨팅으로 계산하지 않는다. [R9]
2026-10-26 현재 오프라인 3라인·3영웅·봇·성장·공성·승패와 자동 검사·실제 렌더 기록을 확보했다. Windows 배포 빌드·Steam 연동·온라인 지연 검증은 미완료이며, Steam 계정·결제·스토어 공개 동작의 실행 기록은 없다. 실행 방법은 [Godot 빠른 시작](../technical/03-godot-quickstart.md), 다음 작업은 [남은 개발 사항](../../doc/design/11-remaining-development.md)을 따른다.
