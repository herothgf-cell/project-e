- 상태: 코드 구현·자동 회귀와 실제 장면의 UI 배치 검사 완료. Windows 실행·사람 가독성·렌더 캡처는 미실시.

## 1. 플레이어에게 보이는 변화

| 상황 | 표시 |
|---|---|
| 현재 관측 중인 셀 생성·재생성 | 약 0.9초 확산 고리와 `셀 등장 · 20/30/40 XP` |
| 본인의 XP 획득 | 수령 지점 위 `+N XP`, 화면 하단의 개인 획득 안내 |
| 여러 영웅에게 분배 | 실제 개인 수령량과 `2명 공유` 등의 인원 표시 |
| 레벨 상승 | 도달 레벨, 새 성장 포인트 수, `G 투자` 안내 |
| 레벨 3 이상이고 미해금 R·남은 포인트가 있음 | `R 해금 가능` 안내. 자동 해금하지 않음 |
| 진행도 | 기존 XP 숫자 위의 얇은 진행 막대; 획득 시 짧은 강조, 최고 레벨은 채워진 상태 |

예시: 40 XP를 두 명이 나누면 각자의 실제 보상은 20 XP다. 세 명은 각각 40/3 XP이며 내부 값은 반올림하지 않고 화면만 `≈13.33`으로 표시한다. 11레벨에서 12레벨까지 10 XP가 남았다면 40 배분 중 성장에 반영된 10만 표시한다. 이미 최고 레벨이면 가짜 XP 숫자를 띄우지 않으며 기존 크레딧 수령 조건은 유지한다.

일반 획득 안내는 1.8초, 레벨업 안내는 3.2초다. 살아 있는 레벨업 안내를 작은 병력 XP가 즉시 덮어쓰지 않는다. 동시에 유지하는 표시를 16개로 제한하고 전장 부동 숫자는 최근 3개까지만 그린다. 일시정지 중 수명은 진행하지 않는다.

## 2. 유지한 규칙

셀 보상 20/30/40, HP 180, 최초 30초·재생성 45초, 생존 아군 영웅 14m 균등 공유, 셀 총 크레딧 10은 바꾸지 않았다. 레벨 요구량·성장 증가량·R 해금 조건, 포탑 8.5m, 고저차·지원 경사, 영웅 능력치·기술·봇 판단·소모품도 유지한다.

이번 작업은 XP를 더 주는 변경이 아니라 **실제 지급 결과를 읽을 수 있게 연결하는 작업**이다. 최고 레벨 초과분은 기존에도 버려졌으며, 그 값을 보상 표시에서 제외하도록 명시했다.

## 3. 정보 노출과 수명 규칙

- 셀이 생성되는 순간 관측 가능했던 팀을 이벤트에 고정한다. 화면에서는 현재 시야와 셀 생존도 다시 확인한다.
- 숨겨진 곳의 생성은 표시하지 않는다. 나중에 이동해서 밝히더라도 옛 생성 효과를 재생하지 않는다.
- 시야를 잃으면 해당 등장 효과를 제거한다. 다시 시야를 얻어도 같은 효과를 재생하지 않는다.
- 개인 XP 이벤트는 수령자 위치·실제 지급량·보상 종류·공유 인원·성장 변화만 전달한다. 처치한 대상의 ID나 위치는 포함하지 않는다.
- 개인 안내는 조작 영웅의 지급만 읽는다. 상대 XP 획득·레벨업 이벤트를 로컬 안내로 보여주지 않는다.
- `match_serial`로 재경기를 구분하므로 ID·이벤트 번호가 재사용돼도 이전 표시를 되살리지 않는다.
- 일반 전투 기록 96개와 별도로 XP/생성 기록 128개를 유지한다. 피해 이벤트 폭증이 최근 획득 표시를 밀어내지 않는다. 이는 짧은 표시용 버퍼이며 영구 경기 기록은 아니다.

## 6. 최종 검토와 미검증 범위

별도 하위 에이전트 리뷰 도구는 없어서 변경 diff·규칙·테스트를 직접 재검토했다. 독립 리뷰 완료라고 기록하지 않는다. 최종 상태 코드의 diff는 이벤트/피드백 추가만 포함하며 기존 이동·공성 블록의 변경은 남지 않았다.

아직 하지 않은 것: 실제 Windows 실행, 실제 렌더 캡처·읽기 쉬움·강조 빈도 확인, 고지/경사에서 사람이 셀을 처치하는 경기, 최신 Windows ZIP 제작, 온라인 이벤트 전송·서버 정보 필터. 로컬 표시 필터를 온라인 보안 구현으로 해석하지 않는다.

사람 확인 순서: 일반 경기에서 관측 중인 셀 등장 확인 → 혼자/아군 근처에서 처치해 지급량 비교 → 레벨업과 G/R 안내 확인 → 일시정지·재시작 후 잔상 확인. 과도한 알림 빈도와 2px 진행 막대의 가독성은 여기서 조정한다.
