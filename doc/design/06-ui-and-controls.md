# 화면·입력과 안내

- 대상: 현재 로컬 봇 경기. 온라인 방·매칭·상점의 화면은 후속 범위다.
- 입력은 표시층에서 명령으로 변환하고 피해·자원·승패를 독자 계산하지 않는다.
- 관련: [전투](03-combat.md), [성장](05-growth-and-economy.md), [초기 모드/UI 제안](../../docs/content/04-modes-onboarding-and-ui.md).

## 1. 현재 조작 규격

| 입력 | 동작 | 경계 |
|---|---|---|
| 우클릭 지면 | 해당 위치로 이동 | 합법 경로를 찾고 물·벽을 통과하지 않음 |
| 우클릭 보이는 적 | 기본 공격 대상을 지정, 사거리까지 접근 | 아군 클릭은 공격 아님; 숨은 적 선택 불가 |
| Q/W/E/R | 해당 기술 조준 시작 | R 잠금·자원·쿨타임 실패를 구분 |
| 조준 중 좌클릭 | 보이는 미리보기의 방향/지점으로 시전 요청 | UI 위 클릭으로 전장 시전하지 않음 |
| Esc | 조준 취소; 조준 중이 아니면 일시정지 메뉴 | 취소로 에너지·쿨타임을 소비하지 않음 |
| S | 현재 이동/공격 명령 중지 | 이미 확정된 효과를 임의로 되돌리지 않음 |
| G | 성장 패널 열기/닫기 | 패널을 연 동안 로컬 경기 일시정지; 포인트·현재 투자·상한·R 해금 표시 |
| B | 기지까지 이동 명령 | 순간이동·상점·회복 즉시 완료가 아님 |
| 마우스 가운데 버튼 드래그 | 전장 카메라 이동 | 전장 이동 명령·기술 시전과 분리 |
| 마우스 휠 | 카메라 확대/축소 | 지면 목표와 HUD가 사용 가능한 범위 유지 |
| Space | 조작 영웅으로 카메라 복귀 | 영웅 사망 중에는 기지/관측 위치를 안전하게 처리 |
| 미니맵 좌클릭 / 우클릭 | 해당 위치로 시점 이동 / 영웅 이동 요청 | 화면 입력을 소비하며 전장 클릭으로 중복 전달하지 않음 |

키 재지정·빠른 시전·핑·D 소모품·T 겹친 표적 순환·키보드 카메라 이동은 실제 구현 근거가 생길 때까지 후속 기능으로 표시한다. 기존 문서의 G 핑/U 성장/B 상점과 현재 키 배치를 혼용하지 않는다.

**바로 다음 개발:** R27로 `A → 전장 지면 좌클릭` 공격 이동을 추가한다. 이동 중 보이는 유효 표적을 기본 공격하고 교전 후 목적지로 복귀하는 명령이다. 현재 키 표에는 아직 구현되지 않은 A를 넣지 않았다. 준비/확정/취소, 자동 표적, 최신 명령 교체와 UI 클릭 차단 기준은 [다음 개발 기획](11-remaining-development.md)을 따른다. R24 셀 XP 종류, R25 시야 방식, R26 포탑 사거리의 확정된 변화도 이 화면과 안내에 반영한다.

## 2. 시작과 결과 화면

시작 화면은 바스·리오·네마의 이름과 전투 주제, 일반 경기/기술 체험의 차이를 설명한다. 일반 경기는 레벨 1·2포인트·R 잠금, 기술 체험은 여섯 영웅 모두 레벨 3·R 해금·잔여 3포인트다. 아군 두 명과 상대 세 명이 봇임을 알린다.

결과 화면은 승리·패배·동시 핵 파괴 무승부를 구분하고 재시작 경로를 제공한다. 현재 제공하지 않는 사람 매칭이나 Steam 초대 버튼을 넣지 않는다. 일시정지는 로컬 시뮬레이션의 시간 진행을 멈추며 온라인 일시정지 정책으로 일반화하지 않는다.

성장 패널도 로컬 시간을 멈춘다. 처음 배우는 사람이 투자 항목을 읽을 수 있게 한 현재 편의이며, 전투 중에도 시간이 흐르는 온라인 성장 화면은 별도 정책으로 설계한다.

## 3. 경기 HUD

| 영역 | 필수 정보 | 주의할 점 |
|---|---|---|
| 상단 | 경기 시간, 양 팀 핵 잠금/파괴 상태 | 12–18분 가설을 강제 종료 타이머로 표시하지 않음 |
| 영웅 주변 | 이름, HP, 보호막, 상태, 선택/이동 표식 | 실루엣과 바닥 경고를 가리지 않음 |
| 기술 영역 | Q/W/E/R, 남은 쿨타임, 에너지 비용, 해금 | R의 레벨 조건과 투자 조건을 구분 |
| 성장 영역 | 레벨, 다음 XP, 미사용 포인트, 투자 선택 | 상한·포인트 부족을 설명; 자동 소비 금지 |
| 미니맵 | N/C/S, 공개 구조물 상태, 아군, 보이는 적 | 숨은 적 위치와 셀 변화를 실시간 추적하지 않음 |
| 안내 영역 | 최근 실패 이유, 사망/부활, 핵 노출, 연습 조건 | 반복 문구가 중요한 메시지를 덮지 않게 제한 |

적 구조물의 파괴·핵 노출은 공개 정보다. 숨은 적 유닛의 HP·레벨·쿨타임·정확한 위치는 제공하지 않는다. 적 구조물 HP는 관측 상태가 명확해야 한다. 아군 구조물은 팀 정보로 공유한다.

패시브 HUD는 바스 압력 0/1/2와 만료, 리오 Q 단계·회수점·E 강화, 네마 핀 수·수명·연결 유효성을 문자로 표시한다. 이것을 최종 전용 아이콘·효과음·단계별 학습 화면까지 제작한 것으로 세지 않는다. 실제 읽기 쉬움은 아래 검증 상태와 별개로 확인한다.

## 4. 조준과 실패 안내

조준 미리보기는 시뮬레이션이 반환한 원·부채·선·삼각형 형상을 사용한다. 리오 R은 내부 전체가 아닌 세 변을 표시한다. 리오 W의 활성 회수점은 바닥 원과 잔여 시간 호로, Q의 복귀 단계는 고정 회수점까지의 선으로 표시한다. 네마의 유효한 두 핀 연결은 폭 0.5m의 지속 띠로 표시한다. 적 연결선과 선형 효과는 현재 관측되는 구간만 보여 숨은 끝점이 드러나지 않게 한다. 네마 W/R은 승인에 참여하는 핀과 형상을 보여 준다. 바스 E는 최대 이동 경로와 지형 차단을 읽을 수 있어야 한다.

현재 원형·부채 경고의 벽 뒤 외곽선은 잘리지 않는다. 벽 너머 대상에는 효과가 없으나 화면에는 원래 형상이 남을 수 있다. [표시 한계 L01](10-differences.md#3-현재-구현의-한계)로 추적하며 판정 영역이 일치했다고 표시하지 않는다.

| 실패 | 짧은 안내 예 |
|---|---|
| R 잠금 | ‘레벨 3부터 성장 1포인트로 해금’ |
| 범위 밖 | ‘사거리 밖입니다’ |
| 에너지 | ‘에너지가 부족합니다’ |
| 지형 | ‘이 지점에는 사용할 수 없습니다’ |
| 네마 장치 | ‘연결된 핀 2개가 필요합니다’ |
| 내곽 잠금 | ‘같은 라인의 외곽탑을 먼저 파괴하세요’ |
| 병력 부재 보호 | ‘아군 라인 병력 12m 안 필요’ |

실패한 요청과 승인 후 중단을 구분한다. 전자는 비용이 없고 후자는 환급하지 않는다. 입력 포커스가 메뉴·버튼·텍스트 입력에 있으면 게임 명령으로 동시에 처리하지 않는다.

## 5. 읽기 쉬움과 후속 학습

팀은 청록/주황 색과 윤곽·표식을 함께 사용한다. 자물쇠(무적 잠금)와 방패(병력 부재 보호)를 분리한다. 설정의 배율·색상 대체·화면 흔들림·번쩍임 감소는 후속 접근성 검증 항목이다. 한국어 HUD용 폰트를 프로젝트에 포함하고, 실제 글리프 표시와 작은 화면에서의 잘림은 실행 프레임으로 확인한다.

후속 튜토리얼은 이동→기본 공격→Q/W/E→성장→라인 보상→연결로 지원→R 해금→기지 회복→공성 보호→핵 파괴 순으로 구성한다. 기술 체험을 제공한 것만으로 튜토리얼 완료를 주장하지 않는다.

## 6. 구현 및 검증 상태

| 항목 | 상태 | 근거/후속 |
|---|---|---|
| 선택·현재 키·조준·결과/재시작 | 화면·입력 코드 반영 | [전장 입력](../../game/project-e/scripts/presentation/battlefield.gd), [HUD](../../game/project-e/scripts/presentation/battle_hud.gd); 실제 라우팅 검증은 별도 |
| HP/에너지·쿨타임·성장 | HUD 코드 반영 | 시뮬레이션 값 참조·성장 버튼·연습 조건; 실행 프레임과 값 비교는 검증 문서 참조 |
| 미니맵·시야·패널 클릭 차단 | 표시/입력 분기 반영 | [미니맵](../../game/project-e/scripts/presentation/tactical_map.gd), [효과](../../game/project-e/scripts/presentation/effects_view.gd); 숨은 표적 회귀와 경고 한계 별도 |
| 패시브 상세 HUD | 문자 상태 표시 반영 | HUD의 압력·원반 단계·회수점/강화·핀 수명; 가독성과 학습 효과 미검증 |
| 키 재지정·핑·접근성 설정·온보딩 | 보류 | 사람 대상 이해도와 배율 검증 필요 |

소스 확인으로 실제 조작·화면 테스트를 대신하지 않는다. 실행한 입력·장면 테스트와 확인 프레임은 [검증 기록](09-verification.md)을 따른다.
