# 로컬 플레이테스트 기록표

- 작성일: 2026-10-27, Asia/Seoul.
- 연결 과제: [R03 실제 Windows PC 실행 / R05 사람 경기와 R09·R10 경제 판단](11-remaining-development.md).
- **현재 기록 상태: 미실시.** 아래 칸은 테스트 절차와 빈 양식이다. 자동 검사·봇 경기·Linux 렌더 캡처를 참가자의 실제 플레이로 입력하지 않는다.
- 빌드 방법과 로그 위치: [Windows 실행 안내](../../docs/technical/04-windows-build.md). 자동 검증과 산출물 근거: [검증 기록](09-verification.md).

| 항목 | 실제 기록 |
|---|---|

| ZIP 파일명·SHA-256 / manifest의 소스 commit | 미실시 |
| Windows 버전 | 미실시 |
| CPU·GPU·RAM | 미실시 |
| 화면 해상도·Windows 배율 | 미실시 |
| 참가자의 AOS/마우스 조작 경험 | 미실시 |
| 테스트 조건 | 사람1명+봇5명, 일반 경기 / 별도로 기술 체험 여부 기록 |

파일을 받은 사람은 ZIP 전체를 푼 뒤 **ProjectE.exe**를 실행한다. ProjectE.pck를 같은 폴더에 둔다. F1에서 조작과 전장 목표를 확인할 수 있다. 일반 경기는 레벨1·성장2포인트, 기술 체험은 레벨3·R 해금 상태다.

기지 상점·소모품이 포함된 빌드에서는 **G 성장/B 기지 이동/P 상점/D 사용**을 확인한다. P→구매→I01/I02 슬롯 클릭으로 종류 선택→D의 순서다. 두 슬롯은 종류별 수량이고 클릭만으로 소비하지 않으며, 빈 선택에서 D를 눌러도 다른 품목을 쓰지 않는다. 소모품 묶음의 자동 검증·화면·새 패키지 상태는 위 manifest와 [최신 검증](13-consumables-verification.md)을 대조한다.12개 묶음3,453 assertion 통과와6봇431.8초 서쪽 승리는 사람의 플레이 결과가 아니며, 아래 실제 기록은 미실시로 유지한다.

### 현재 전달 기준 패키지

아래는 참가자가 직접 테스트한 결과가 아니라 **테스트에 사용할 빌드의 식별 정보**다. 위 실제 기록 칸의 ‘미실시’는 유지하며, 실제로 받은 ZIP의 해시와 manifest를 대조한 뒤 참가자·장비·일시와 함께 채운다.

| 항목 | 기준 |
|---|---|
| 소스 commit | `e56286a064063bda84ccd9eb309ab8fb80a575a1` |
| 파일·크기 | `ProjectE-windows-x86_64.zip`,39,428,780바이트 |
| SHA-256 | `a2d88d42da7623d4ddb71420af2fce2dd7b30a67cac87bca7616fd153a43ae4d` |
| 확보한 자동/산출물 근거 | 공식 release export·ZIP/manifest 독립 검토 PASS, 소스 밖 Linux PCK90프레임·headless 소모품10/0·GL13/0와3프레임 |
| 실제 Windows PC·사람 경기 | **미실시** |

현재 패키지는 소모품이 포함된 새 빌드이며 기존 다운로드 항목을 이 ZIP으로 갱신했다. 이전 `a11834f`/`4bcc…` ZIP은 과거 산출물이며, 현재 파일을 확인할 때는 [manifest](verification/2026-10-27-consumables-windows-manifest.json)와 [빌드 안내](../../docs/technical/04-windows-build.md#7-현재-소모품-테스트-패키지)를 사용한다. Linux PCK 검증은 Windows EXE 실행·물리 입력·Alt-Tab·DPI·사람 플레이 확인을 대신하지 않는다.

분류는 **결함**, **이해/가독성**, **밸런스 가설**, **취향/제안**으로 구별한다. 진행 불가·잘못된 피해/보상·숨은 정보 노출은 먼저 수정한다. 반복되는 조작·읽기 문제를 그다음에 다루고 수치 조정은 근거 장면과 바뀌는 변수를 명시한다.
