# V6 화면·카메라·전투 흐름 수정 계획

기준은 2026-11-06의 main `220e4f9`다. 사용자가 첨부한 선택 화면과 시안의 차이, 오른쪽 화면 끝에서만 반응하는 카메라, 첨부한 9쪽 PDF를 작업 근거로 삼는다.

## 확인한 문제

현재 선택 화면은 작은 초상과 설명을 고정 폭 카드에 넣고 있다. 전투 HUD는 상단 바, 미니맵, 소모품 바, 하단 상태창이 전장을 넓게 가린다. 카메라는 끝 12픽셀에서 일정 속도로 이동하며 HUD 전체를 이동 금지 영역으로 처리한다. 기본 카메라 추적은 꺼져 있다.

## 구현과 확인 순서

1. 영웅 선택은 기존 일러스트와 수로 원화를 크게 사용하고 선택 상태, 역할, 일반 경기와 기술 체험의 차이를 읽기 쉽게 정리한다. 전투 HUD는 높이와 여백을 줄이고 상태·스킬·소모품 조작을 보존한다.
2. 카메라는 화면 가장자리의 일관된 반응과 속도 변화를 제공한다. 시작 시 영웅을 부드럽게 따라가며 수동 이동, Y 추적 전환, Space 복귀, 확대·축소를 함께 검증한다. 모달·앱 포커스·화면 밖 포인터는 별도로 확인한다.
3. PDF 4쪽 특징과 5쪽 전투 팁을 현재 전투 규칙과 비교한다. 단일 변경의 이유와 실제 수치는 대응 문서에 남기고 회귀 검사로 증명한다.
4. 새 테스트를 전체 실행 목록에 등록한다. 1280×720, 1366×768, 960×540에서 선택 화면을 실제 렌더링하고 경기 화면과 HUD 겹침을 확인한다.
5. Windows 배포 PCK 자체에서도 같은 선택 화면과 자산을 확인한다. 실행 파일의 Windows 기동, 전체 회귀 검사, 최종 커밋과 패키지 소스 일치 여부를 확인한다.

## 이번 구현의 판단

기존 Godot 프로젝트와 아트 자산을 사용한다. 첫 실행의 카메라 추적과 가장자리 반응 범위는 조작 불편을 줄이기 위한 구현 판단이며, 단축키로 자유 시점을 선택할 수 있게 한다. PDF의 수치와 이름은 현재 전투의 설계 목적과 검증 결과에 따라 반영한다.
