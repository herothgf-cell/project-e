## 1. 이번에 확인한 것과 남은 자료

참고 링크는 [「【랑튜브】 희귀영상 — 시티오브템페스트의 전설 윤완진 플레이 영상 단독입수」](https://www.youtube.com/watch?v=B0V1yRqhIc8)다. 브라우저에서 제목과 재생 길이 **23분37초**를 확인했다. 그러나 플레이어는 재생 데이터가 로드되지 않아 0:00의 검은 화면에 머물렀고, 영상 내려받기도 실패했다. 별도의 공개 영상 읽기 경로에서는 YouTube가 **로그인하여 자동 접근이 아님을 확인하라는 응답**을 반환했다. 접근 제한을 우회하지 않았으며 실제 플레이 프레임·자막·음성을 확보하지 못했다.

따라서 이 문서는 **영상에서 특정 장면을 보았다는 기록이 아니다**. 현재 저장소의 구현과 사용자가 지정한 다섯 관점을 연결한 개발 재정리다. 영상의 언덕 시야 규칙, XP 생성 방식·주기, 정확한 타워 수·좌표, 특정 영웅의 기술·콤보, 실제 전투 속도는 미확인이다. 장면의 타임스탬프나 원작 수치를 만들어 기입하지 않는다.

영상 파일 또는 주요 장면 클립이 확보되면 아래 관측표를 채워 권장안을 보완한다. 정지 이미지는 배치·표시 확인에 쓸 수 있지만 스킬 연결과 이동 속도 판단에는 시간 정보가 있는 연속 장면이 필요하다.

|---|---|---|
| 맵 전체·라인 전환 | 실제 통로, 경사·절벽, 진입·우회·퇴각 선택, 합류 출발/도착 시각 | 장면 미확인 |

한 화면에서 적이 안 보인다는 사실만으로 고저차 때문이라고 결론 내리지 않는다. 카메라 이동, 평면 시야 차단, 은폐, 편집·재생 배속 같은 다른 설명을 확인해야 한다. 영상 길이23:37도 한 판의 실제 경기 시간과 같다고 가정하지 않는다.

## 2. 재정리의 중심

권장 방향은 **지형·성장 자원·포탑이 이동과 교전 선택을 만들고, 그 선택을 짧은 입력과 읽기 쉬운 전투 반응으로 연결하는 것**이다.

다음 작업의 중심을 기능 수 증가에서 아래 두 묶음으로 옮긴다.

1. **행동과 보상 이해:** 입력 접수/예약/실패, 공격·시전·피격, XP 등장·실제 지급·레벨업, 포탑의 표적·보복을 읽을 수 있게 한다.
2. **공간에서의 선택:** 작은 고저차 구역에서 안전한 우회, 빠른 합류, XP 경합, 공성 진입과 퇴각을 시험한다.

이는 기존 제품 목표인 빠른 기술 교환·3대3/3라인·경기 중 성장·지원·공성을 구체화하는 제안이다. 원작의 영웅과 맵을 일대일로 복제한다는 결정이 아니다. 기존 목표와 독립적인 기술·상대법의 기준은 [제품 개요](../../docs/00-project-brief.md)와 [결정 이력](../../docs/05-decisions-and-sources.md)에 유지한다.

### 검토한 접근

| 접근 | 얻는 것 | 한계와 판단 |
|---|---|---|
| 지형 외형과 이펙트부터 확대 | 높낮이와 속도감의 시각적 인상 | 현재 평면 판정과 어긋날 수 있고 선택 구조를 검증하기 어렵다. 주된 개발 순서로 권하지 않음 |
| **작은 전투 구역의 규칙·표시·동선부터 연결** | 현재 세 영웅과 기능을 사용해 지형·성장·공성의 상호작용을 확인 | 클릭·길찾기·시야·기술의 공통 계약 작업이 필요함. **권장안** |

이 선택은 검토자가 제안한 방향이며 사용자가 세부 고저차 규칙이나 새로운 수치를 확정했다는 뜻은 아니다.

## 4. 맵 구조 — 실제 고저차와 합류 선택

### 4.1 현재 제약

현재 맵의 명목 라인 길이는 중앙100m, 북·남112m이며 연결로 중심선은 각각 약21.63m다. 명목 폭은 라인6m·연결로4m다. 단순 이동속도로 나눈 연결로3.5–3.8초는 입구→출구의 계산값으로, 지원을 결정한 위치에서 교전에 합류한 실측 시간이 아니다. [M01 기획](02-map-m01.md)

고저차를 만들 때는 지면 메시만 높여서는 충분하지 않다. 현재 클릭은 `Plane(Vector3.UP,0)`을 사용하고 유닛 발·표적 클릭·HP바·경고도 평면을 전제로 한다. 길찾기는1m 격자에0.58m 여유를 사용하는 `AStarGrid2D`이며, 좁은 경사 입구는 시각적으로 열려 있어도 경로가 끊길 수 있다. 현재 단일 LOS 함수는 시야 외에도 평타·원반·핀·연결선·경고 형상에 사용된다. [맵](../../game/project-e/scripts/battle/battle_map.gd) · [입력/유닛 표시](../../game/project-e/scripts/presentation/battlefield.gd) · [HP바/셀 표시](../../game/project-e/scripts/presentation/unit_overlay.gd)

### 4.2 권장 첫 구현 범위

**평지 → 경사로 → 고지 → 절벽이 있는 한 구역**부터 만든다. 기존 M01의 연결로/셀 구역을 시험 대상으로 삼고, 정규 경기에 통합할 때는 대응하는 반대편 구역도 함께 검토한다. 맵 전체의 고저차 제작과 자유로운 점프·비행·물리 시뮬레이션까지 동시에 확장하지 않는다.

현재 구조를 활용하는 구현 방향은 **평면 이동 좌표에 지형 높이와 연결 규칙을 추가하는2.5D 방식**이다. 맵이 높이 질의·통행 연결·절벽 경계를 제공하고, 입력·발 위치·표적·경고가 같은 데이터를 사용한다. 이것은 구현 권장안이며 현재 제공되는 기능이 아니다.

먼저 정할 규칙은 다음과 같다.

| 항목 | 권장 초안 | 확인해야 할 문제 |
|---|---|---|
| 보행 | 높이가 바뀌는 곳은 지정 경사 연결로 통과 | 경사 시작/끝·모서리·두 유닛 교행에서 정지하지 않는가 |
| 고저차 시야 | 낮은 곳에서 고지 내부를 바로 보지 못하고, 높은 곳도 벽의 차단은 받음 | 아군 고지 관측자와 팀 공유 시야가 일관되는가 |
| 사거리 | 우선 기존 평면 거리 의미를 유지 | 높이 추가가 의도치 않은 사거리 보너스로 작동하지 않는가 |
| 공격·기술 | 시야 차단과 투사체/지면 효과 차단을 분리해 기술별로 결정 | 보이지 않는 대상을 자동 표적하거나 표시로 노출하지 않는가 |
| 이동기 | 바스/리오 지면 돌진은 유효 경사와 지면 연결을 따름 | 경고 끝점과 실제 도착점이 같은가 |
| 고지의 대응 가능성 | 공격 시 일시 노출 등 대응 장치를 별도 검토 | 고지에서 일방 공격만 반복되는가, 관측/우회로 대응 가능한가 |

마지막 행의 노출 방식·지속시간과 세부 고저차 공격 허용은 **미확정**이다. 원작 규칙을 영상에서 확인한 사실로 쓰지 않는다. 네마 핀과 리오 회수점에 새 시야 능력을 부여하는 것도 별도의 게임 규칙 결정이다. 현재 이 설치물들이 시야를 준다고 가정하지 않는다.

**끝났다고 판단할 기준:** 세 영웅이 경사로를 오르내리고, 클릭한 지면·발 위치·HP바·스킬 경고가 일치한다. 절벽을 보행/돌진으로 관통하지 않으며, 고저차에 따른 시야·자동 표적·평타·원반 왕복·핀 연결이 확정 규칙과 일치한다. 이후 실제 합류/복귀 시간과 고지 선택 이유를 기록한다.

### 5.2 다음 작업

1. **등장 알림:** 현재 관측 중인 셀이 나타날 때 짧은 점등·확산과 상태 변화를 보여 준다. 재생성 예고는 관측으로 알 수 있는 정보만 사용한다. 아직 본 적 없는 곳이나 시야 밖 적 행동을 전역 타이머로 알려주지 않는다.
2. **실제 지급 피드백:** 셀 파괴 시 XP 흐름·`+XP`·게이지·레벨업/성장 포인트를 연결한다. 효과는 권한이 계산한 수령자와 실제 지급량에서 만든다. 눈앞의 숫자20/30/40이 혼자 항상 전부 받는 양처럼 보이지 않게 한다.
3. **축소 화면 가독성:** 필드와 미니맵에서 등급을 형태/크기로 구별하고 현재 관측 정책을 유지한다.
4. **위치의 의미:**20은 안전한 짧은 우회,30은 라인 이탈,40은 상대와 경합할 수 있는 위치로 구분하는 배치를 시험한다. 이는 새 배치 가설이며 현행 배치가 이미 그 역할을 보장한다는 뜻이 아니다.
5. **상대의 경쟁:** R10 봇이 셀을 선택·접근·포기·복귀할 수 있게 한다. A 공격 이동은 현재 셀/핀을 자동 표적으로 삼지 않으므로 이 계약을 실수로 바꾸지 않는다.

첫 비교에서는 현재 XP 총량과30/45초 기준을 유지하고 위치와 표시의 영향을 먼저 본다. 새로운 대형 XP 목표물, 랜덤 생성, 성장 배율 상향은 그 뒤의 선택지다. 영상에서 픽업형 자원이 확인되더라도 현재 파괴형 셀을 곧바로 교체하지 않고 획득 방식이 만드는 판단을 비교한다.

**완료 기준:** 등장·파괴·공유·레벨업을 플레이어가 설명할 수 있다. 여러 영웅에게 나눠 준 표시의 합이 실제 지급과 일치하고 시야 밖 재생성·적 획득을 누설하지 않는다. 셀을 먹느라 비운 라인의 손실과 얻은 성장 이득을 함께 기록한다.

## 6. 타워 — 보호 범위와 열린 전투 공간 함께 설계

현재 총12개 타워는 각 팀의 세 라인에 외곽/내곽으로 배치된다. 북·남 외곽 x=±10, 내곽 x=±26, 중앙 내곽 x=±30이며 라인 중심에서 옆으로3.5m 떨어져 있다. 공격8.5m는 탑 중심→대상 외곽 거리이고, 시야12m와 병력 보호 해제12m는 다른 의미다. [좌표](02-map-m01.md) · [맵 코드](../../game/project-e/scripts/battle/battle_map.gd)

영웅/핀의 구조물 피해는 기본×0.5이고 공격 팀 병력이12m 안에 없으면 추가×0.3이라 합쳐15%가 된다. 이 병력 조건은 특정 공성 병종만을 뜻하지 않는다. 내곽은 같은 라인 외곽이 파괴돼야, 핵은 내곽 하나가 파괴돼야 공격 가능하다. 보복 표적3초와 일반 병력 우선 표적 선택도 이미 있다. [전투 규칙](../../game/project-e/scripts/battle/battle_rules.gd) · [탑 AI](../../game/project-e/scripts/battle/battle_ai.gd)

다음은 사거리 재축소부터 시작하지 않고 **탑 앞·옆·뒤에서 가능한 행동**을 검사하는 것이다.

- 병력과 함께 들어갈 공성 자리와 안전하게 기다릴 자리가 구분되는가.
- 고지나 경사로에서 진입한 뒤 퇴각할 경로가 존재하는가.
- 연결로와 XP 진입로가 두 타워의 공격/시야에 과도하게 덮이지 않는가.
- 타워가 누구를 공격하려는지, 영웅 공격 때문에 보복이 시작됐는지, 왜 피해가 크게 줄었는지 보이는가.
- 타워 파괴 뒤 전진/우회 공간이 어떻게 달라지는가. 현재 구조물 충돌 원은 생성 시 고정되므로 파괴 후 통로 개방을 새 기능처럼 가정하지 않는다.

첫 배치 실험은 탑 개수·피해·HP·사거리8.5m를 기준값으로 두고 위치와 진입/퇴각 지형을 비교한다. 고지 판정이 정리된 뒤 전체 배치를 조정해 같은 일을 반복하지 않게 한다.

**완료 기준:** 근접/원거리 영웅 각각의 접근·공격·퇴각을 확인하고, 거리 표시·투사체·실제 타깃·봇 위험 판단이 같은 배치를 사용한다. 탑이 너무 안전하거나 아무 기능을 못 하는 구간은 체류·공격·퇴각 기록으로 설명한다.

## 7. 스킬 — 입력과 행동 연결, 대응 가능한 표현

현재 일반 기술의 재사용 대기는2.5–5.5초, R은15–18초다. 선딜은0.06–0.65초, 후딜은0.12–0.25초다. 기본 공격 주기는 전원1초, 선딜은0.16–0.18초다. 재사용 대기는 공격/시전 시작부터 감소하므로 선딜·후딜을 다시 더해 주기라고 설명하면 안 된다. [기술 데이터](../../game/project-e/scripts/battle/hero_abilities.gd) · [전투 처리](../../game/project-e/scripts/battle/battle_state.gd)

QWER는 현재 키로 조준을 켜고 좌클릭으로 확정한다. 기술은 진행 중인 기본 공격·시전·돌진·후딜 뒤에 최신 유효 명령 하나를 예약하며, 이동은 기본 공격을 취소할 수 있다. 이 정책과 현재 입력 부담을 읽지 않고 모든 쿨타임을 줄이면 체감 원인을 분리하기 어렵다. [입력](../../game/project-e/scripts/presentation/battlefield.gd) · [예약 명령](03-combat.md)

다음 범위를 권한다.

| 작업 | 목적 | 확인 기준 |
|---|---|---|
| 접수·예약·실패 표시 | 눌렀는데 안 나간 것과 의도된 대기를 구별 | 실제 명령 승인/예약/거절 상태와 일치 |
| 선택적 빠른 시전 시험 | 일반 조준 외에 키를 누르는 동안 범위, 떼면 확정하는 입력을 한 영웅부터 비교 | Esc/메뉴/사망/기절/예약 교체에서 오발·중복 소비 없음 |
| 최소 동작·타격음·제어 표시 | 기본 공격 준비/발사, 기술 선딜/활성/후딜, 피격·기절·속박을 구별 | 권한 단계와 표시가 맞고 숨은 적 적중 정보가 새지 않음 |
| 연결 장면 반복 | 이동→평타→기술→퇴각의 답답한 지점을 찾기 | 입력 시각, 승인/예약, 발동, 다음 행동 가능 시각을 분리 기록 |
| 지형별 세 영웅 상대법 | 바스의 진입, 리오 왕복 경로, 네마 핀/연결을 공간 선택에 연결 | 좁은 경사에서 일방 봉쇄가 아닌 회피·파괴·우회 선택 존재 |

빠른 시전은 이번에 구현되거나 기본 입력으로 확정된 기능이 아니다. 기절 등 유효하지 않은 상태를 무시하는 입력으로 만들지 않으며, 읽어야 할 위험 기술의 선딜을 단순히 제거하는 것도 별도 판단이다. 완성 애니메이션·신규 영웅 증량보다 현재 세 영웅의 연결과 상대법 확인을 먼저 권한다.

## 10. 다음 한 묶음의 구체적 범위

바로 다음 구현 묶음으로는 **입력·보상 피드백과 고저차 실험을 준비하는 최소 도구**를 권한다. 세 묶음을 한꺼번에 끝났다고 처리하지 않고 각각 확인 가능한 단위로 나눈다.

- **묶음 A:** 명령 접수/예약/실패, 기본 공격·기술 단계·타워 표적의 최소 표시, XP 생성·실제 수령·레벨업 피드백. 같은 조건을 반복할 작은 연습/초기화와 사건 기록.
- **묶음 B:** 단일 고저차 구역, 높이 질의/경사 연결, 높이 있는 클릭·유닛·경고, 고저차 시야와 세 영웅의 기술 경계.
- **묶음 C:** 검증된 구역을 M01에 대칭적으로 통합하고 셀/포탑/지원 경로를 조정. 봇 지원·셀 경합과 사람의 합류·퇴각·성장 선택 비교.

최종 아트·새 영웅·장비 조합·다른 맵·공개 매칭의 확대는 이번 우선 묶음 밖이다. 실제 영상이 확보되기 전에는 원작과의 구체적인 차이를 근거로 캐릭터/맵을 교체하지 않는다.
