# 시티 오브 템페스트 참고 요청과 개발 우선순위

- 갱신: **2026-10-29, Asia/Seoul**.
- 참고 링크: `https://www.youtube.com/watch?v=B0V1yRqhIc8`.
- 자료 상태: 영상 페이지 제목·길이는 확인했지만, 이 실행 환경에서는 실제 연속 플레이 프레임을 확보하지 못했다. 따라서 원작의 정확한 좌표·수치·언덕 규칙·스킬 동작을 관찰 사실처럼 쓰지 않는다.
- 현재 상태: 사용자가 지정한 다섯 관점과 Project E 코드 감사를 바탕으로 R28 고저차와 R30 고지–지원 동선을 구현·검증했다.
- 구현 증거: [R28](15-high-ground-verification.md) · [R30](16-r30-high-ground-flow-verification.md).

## 1. 참고 방향

Project E가 가져갈 핵심은 특정 맵·영웅을 복제하는 것이 아니라 다음의 상호작용이다.

> **지형·성장 목표·포탑이 이동 선택을 만들고, 그 선택이 짧은 입력과 빠른 전투 피드백으로 이어지는 구조**

이를 다섯 관점으로 나눈다.

| 관점 | 현재 확보 | 다음 핵심 |
|---|---|---|
| 맵·언덕 |40XP 고지2곳, 각 라인 복귀/지원 경사, 고저차 시야 | 실제 사람의 회전·매복·퇴각 선택, 전체 맵 확대 여부 |
| 경험치 등장 | 파괴형 셀6개,20/30/40,30/45초 | 등장·개인 지급·공유·레벨업 피드백과 봇 경합 |
| 타워 배치 | 양 팀12개,8.5m 공격·12m 시야·병력 공성 보호 | 고지/지원 경사 입구와 포탑 진입·퇴각 체감 |
| 스킬 | 세 영웅 평타·패시브·QWER와 예약 명령 | 입력 즉시/예약/실패, 최소 동작·피격·CC 표현 |
| 스피디함 | 짧은 일반기 쿨타임, 공격 이동, 회전 경로 | 입력·합류·재진입·공성 시간을 각각 측정해 병목별 조정 |

## 2. 영상 근거의 한계

이번 링크는 원작의 분위기와 검토 관점을 알려주는 참고 자료다. 실제 장면을 확보하지 못했으므로 다음은 아직 확인되지 않았다.

- 정확한 라인 수·경사·절벽·우회 경로.
- XP가 파괴형인지 픽업형인지, 생성 주기와 공유 방식.
- 타워 수·좌표·사거리와 어그로 규칙.
- 특정 영웅의 기술·콤보·입력 방식.
- 영상 편집·배속을 제외한 실제 이동·전투 속도.

따라서 Project E의 R28/R30 규칙은 **현재 게임에 적합한 독립 설계**다. 영상에서 그대로 확인한 원작 규칙이 아니다. 영상 파일이나 주요 연속 클립을 확보하면 장면 타임스탬프, 직접 관찰 사실, Project E 제안을 구분해 다시 기록한다.

## 3. 맵·언덕 — 구현된 R28/R30

### R28 첫 고저차

- 북서40XP `(−18,24)`와 남동40XP `(18,−24)`을 높이2.4m로 구성.
- 기존 라인 진입로를 폭3m 경사로 사용.
- 낮은 영웅·병력은 고지를 팀 시야로 밝히지 못하고, 고지에서는 아래를 관측.
- 포탑·핵은12m 안의 고지를 감시해 원거리 일방 공성 사각 방지.
- 유닛·클릭·HP바·스킬 경고·시야 윤곽이 같은 높이 필드를 사용.

### R30 지원 동선

각 고지에 두 번째 경사를 추가했다.

```text
북서 40XP (-18,24)
      ├─ 라인 복귀 → (-18,18)
      └─ 지원 회전 → (-12,18) → K01 (-10,18) → 중앙 연결로

남동 40XP (18,-24)
      ├─ 라인 복귀 → (18,-18)
      └─ 지원 회전 → (12,-18) → K04 (10,-18) → 중앙 연결로
```

의도는 XP를 먹은 뒤 자동으로 같은 길로 되돌아가는 것이 아니라 다음 중 하나를 고르게 하는 것이다.

1. 자신의 라인에 복귀한다.
2. 인접 교전을 지원한다.
3. 상대 지원이 예상되면 고지를 포기한다.
4. 전투 후 원래 라인으로 돌아가 손실을 줄인다.

타워·XP·영웅 수치는 그대로 두어 배치 효과만 분리했다. R30 자동 검사는 경로가 기존 라인 경유보다 짧고, 폭3m 내부가 보행 가능하며, 경사 중심선이 포탑 충돌을 피하는지 확인한다. 실제 재미는 사람 경기에서 검증한다.

## 4. 경험치 — 다음 R29

현재 XP 셀은 공격해 파괴하는 중립 목표다.

-20/30/40XP 각2개.
- HP180, 첫 생성30초, 재생성45초.
- 처치 팀의 살아 있는14m 내 영웅에게 균등 공유.
- 셀당 크레딧 총10.
- 셀은 시야를 제공하지 않음.

R30으로 40XP 획득 뒤 지원 회전 경로가 생겼지만, 보상 흐름은 아직 충분히 읽히지 않는다. 다음 R29는 값과 주기를 바꾸지 않고 다음을 구현한다.

1. 현재 팀 시야 안에서 생성될 때 짧은 등장 표시.
2. 권한이 실제 지급한 개인 XP를 표시.
3. XP 게이지·레벨업·성장 포인트를 한 흐름으로 연결.
4. 여러 명 공유 시 화면 합계와 권한 합계 일치.
5. 시야 밖 생성·적 획득·셀 상태를 누설하지 않음.

이후 사람 테스트에서20은 안전한 짧은 우회,30은 라인 이탈,40은 지원·경합이 필요한 목표로 기능하는지 본다. 필요하면 위치를 조정하되 XP 총량과 주기를 동시에 바꾸지 않는다.

## 5. 타워 — 배치보다 먼저 확인할 것

현재 외곽·내곽 타워는 각 팀3라인에 하나씩, 총12개다.

- 외곽HP2,000, 내곽HP2,600.
- 공격8.5m, 원피해180, 간격1초.
- 구조물 시야12m.
- 공격 팀 병력이12m 안에 없으면 영웅/핀의 구조물 피해가 크게 감소.
- 내곽과 핵은 앞 구조물 파괴 전 잠금.

R30에서 새 지원 경사는 포탑 좌표와 공격 범위를 변경하지 않았다. 다음 사람 관찰에서는 다음을 기록한다.

- 경사 입구가 포탑 공격에 지나치게 덮이는지.
- XP 획득 후 공성으로 이어질지, 지원으로 빠질지 선택이 있는지.
- 근접·원거리 영웅의 접근·공격·퇴각이 모두 가능한지.
- 포탑 표적·보복·병력 보호 이유를 이해하는지.
- 고지에서 포탑을 일방적으로 때리는 구간이 없는지.

문제가 확인될 때 좌표·공격 범위·병력 보호 중 한 변수를 선택해 조정한다.

## 6. 스킬 — 속도 수치보다 입력 연결

현재 일반 스킬 쿨타임은 대체로2.5–5.5초, 궁극기는15–18초다. QWER는 키로 조준하고 좌클릭으로 확정하며, 현재 행동 중 입력은 최신 유효 명령 하나로 예약될 수 있다.

빠르지 않게 느껴지는 원인이 반드시 쿨타임은 아니다.

| 체감 문제 | 먼저 확인할 것 |
|---|---|
| 눌렀는데 안 나감 | 접수·예약·거절 표시 누락 |
| 다음 행동이 늦음 | 선딜·후딜·예약 교체 규칙 |
| 기술을 맞았는지 모름 | 적중·피격·보호막·CC 표현 |
| 회전 후 교전이 끊김 | 경로·시야·카메라·표적 획득 |

R31 권장 범위:

- 즉시 실행 / 예약 / 실패 표시.
- 기본 공격 준비·발사와 기술 선딜·활성·후딜 구분.
- 기절·속박·강화 공격·타워 표적 표시.
- 빠른 시전은 한 영웅에서 선택적으로 비교하며 기본 조작으로 즉시 확정하지 않음.

## 7. 스피디함 — 다섯 시간을 분리

짧은 경기와 빠른 조작감은 별개다.

| 층 | 기록할 사건 |
|---|---|
| 입력 반응 | 키/클릭→접수·예약·실패 표시 |
| 행동 연결 | 확정→선딜→효과→후딜→다음 행동 |
| 합류 | 라인/고지에서 지원 결정→교전 도착 |
| 재진입 | 후퇴·회복·사망→다음 전투 기여 |
| 경기 압박 | 첫 셀·L3/R·첫 탑·핵 노출·종료 |

소모품 추가 후 자동6봇 진단은431.8초에 종료되지만, 봇은 아직 XP 셀과 신규 경사를 전략적으로 사용하지 않는다. 따라서 이 수치로 R30이 빨라졌다고 판단하지 않는다.

R32에서는 같은 빌드·영웅·진영을 기록하고 진영 교대 반복을 포함한다. 느린 원인이 확인된 뒤 이동속도·쿨타임·부활·웨이브·회복 중 하나씩 조정한다.

## 9. 이번 재정리의 증거 경계

확인한 사실:

- 현재 저장소 코드와 자동 검사.
- R28·R30의 좌표·높이·경로·표현.
- Godot4.7.2 CI 결과.

확인하지 않은 것:

- 제공 영상의 실제 장면과 원작 수치.
- 사람의 조작감·재미·균형.
- 실제 Windows 성능.
- 온라인 상태 일치.

이 네 범주를 이후 문서에서도 섞지 않는다.
