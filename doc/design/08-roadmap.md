# 개발 로드맵과 진행 게이트

- 갱신: **2026-10-29, Asia/Seoul**.
- 원칙: 로컬 실행, 자동 검증, 실제 Windows 확인, 사람 게임성 검증, 온라인 품질, 출시 준비를 별도 게이트로 관리한다.
- 관련: [현재 백로그](11-remaining-development.md) · [온라인 기술 계획](../../docs/technical/02-architecture-and-networking.md) · [Steam 계획](../../docs/release/01-steam-release-plan.md).
- 출시일·인원·예산은 확정하지 않는다.

## 1. 현재 단계

Project E는 M01 한 맵과 바스·리오·네마로 사람1명+봇5명의 로컬3대3 한 판을 진행할 수 있다.

| 묶음 | 현재 상태 | 증거 경계 |
|---|---|---|
| 전투·한 판 | 평타·QWER·봇·성장·공성·승패·재시작 연결 | 자동 회귀 통과; 사람 조작감 미검증 |
| 조작·시야 | A 공격 이동, 표적 우선순위, 벽 경고, 팀 시야 음영·시야원 | 화면/회귀 통과; 실제 Windows 성능 미검증 |
| 성장·경제 | XP20/30/40, 포인트·R, 상점·소모품2종, 봇 구매/사용 | 권한/입력/봇 자동 검증; 사람 선택 미검증 |
| R28 공간 |40XP 고지2곳, 라인 경사, 고저차 시야·클릭·경고 |17개 신규 검사; 사람 고지 상대법 미검증 |
| R30 공간 | 각40XP에 지원 경사, 기존 연결로로 빠른 회전,3D·미니맵 |61개 신규 검사; 사람 회전·포탑 체감 미검증 |
| Windows | 소모품 단계 ZIP 제작·검증 | R28/R30 미포함, 실제 Windows PC 미실시 |
| 온라인 | 권한/표시 분리 설계 | 전송·예측·보정·방·복귀 미구현 |

최종 R30 자동 결과는 [Godot regression #19](https://github.com/herothgf-cell/project-e/actions/runs/40811635924)에서 **14묶음·3,531 assertions·실패0**, 프로젝트 import와 메인 장면 시작 PASS다. 이 결과는 사람 재미·균형·Windows 성능·온라인 품질을 대신하지 않는다.

## 2. 단계별 진행

### A. 로컬 공간과 보상 이해 — 현재

완료:

- R01/R02/R04: 클릭·벽 경고·F1 안내.
- R24–R27: 셀 종류, 시야, 포탑8.5m, A 공격 이동.
- R09와 R10 일부: 상점·소모품과 봇 구매/사용.
- R28: 첫 고저차 구역.
- R30: 고지→지원 연결로 회전.

다음:

1. R29 XP 등장·실제 분배·레벨업 피드백.
2. R10 후속 봇의 핵/빈 라인 방어·지원·셀/핀 판단.
3. R31 입력 접수/예약/실패와 최소 전투 표현.
4. R32 사람 템포 비교.

**A 종료 기준:** 처음 보는 사람이 이동·성장·고지 XP·지원·공성 이유를 설명하고, 진행 불가·잘못된 보상·숨은 정보 노출 없이 일반 경기와 재시작을 완료한다.

### B. 실제 Windows와 작은 온라인 진단 — 병행

- 최신 R28/R30 소스로 Windows release ZIP 재생성.
- Godot 없는 Windows PC에서 압축 해제→실행→경기→재시작.
-100/150/200% 배율, Alt-Tab, 로그, 병력/시야/경사 중첩 성능 기록.
- 작은2클라이언트 장면에서 이동·평타·바스E 권한과 예측/보정 확인.

**B 종료 기준:** 실제 Windows 장비에서 한 판이 진행되고,2클라이언트가 같은 이동·피해·자원을 보며 중복 효과가 없다.

### C.6인 비공개 온라인

- R13: 세 영웅·세 라인·병력·탑·셀·성장·소모품·승패 복제.
- R14: 방 생성/참가, 팀·영웅 선택, 준비, 결과, 재경기.
- R15: 연결 손실, 봇 인계, 재접속, 호스트 종료.

**C 종료 기준:** 사람6명이 접속→한 판→결과→재경기를 완료하고, 숨은 적 정보·동시 판정·재접속 상태가 일치한다.

### D. 게임용 자산·성능·접근성

- R16: 영웅1종과 맵 한 구역의 실제 모델·재질·리그·동작부터 검증.
- R17: 아이콘·VFX·공격/기술/피격/실패·핵 경고 음향.
- R18: 대상 PC 프레임 시간·메모리·장시간 재경기.
- R19: UI 크기·색상 외 형태·번쩍임/흔들림·현지화.
- R20: 검사→export→패키징→버전·로그·복구 자동화.

**D 종료 기준:** 전투 가독성·대상 PC 성능·접근성·반복 빌드가 측정과 재현 기록으로 확인된다.

### E. Steam 외부 테스트와 출시 후보

- R21: 인증·오버레이·로비·친구 초대·게임 연결.
- R22: 외부 Playtest 설치·업데이트·접속·완주·재방문과 운영 방식 결정.
- R23: 이름·가격·언어·사양·스토어 자료·제출/검수·긴급 패치·이전 빌드 복구.

**E 종료 기준:** 공개 기능·지원 PC·업데이트·운영 비용·지원 경로가 검증된 출시 후보와 연결된다.

## 3. 핵심 게임성 관찰

| 질문 | 관측 | 먼저 조정할 것 |
|---|---|---|
| 고지40XP를 갈 이유가 있는가? | 획득/포기, 공유 인원, 비운 라인 손실 | 위치·피드백; XP 값/주기는 후순위 |
| 두 경사의 선택이 다른가? | 라인 복귀/지원 회전 비율, 합류·복귀 시간 | 입구 위치·가독성·경로 폭 |
| 인접 지원이 항상 이득인가? | 지원 이득 vs XP·타워 손실 | 연결로·웨이브·봇 복귀 판단 |
| 포탑 앞에서 대응 가능한가? | 근접/원거리 진입·공격·퇴각, 보복 원인 | 배치·표시; 사거리/피해는 근거 후 조정 |
| 스킬 연결이 빠르게 느껴지는가? | 입력→접수/예약→발동→다음 행동 | 입력 피드백·후딜·예약 규칙 |
| 성장 선택이 구별되는가? | 투자·R 해금·소모품 사용과 전투 결과 | 안내·효과 차이; 자동 성장과 분리 |
|12–18분 목표가 적절한가? | 사람6인 중앙값과 종료 원인 | 압박·복귀·공성 기회, 강제 종료 금지 |

봇 한 경기나 작은 승률 표본으로 위 질문을 통과 처리하지 않는다.

## 4. 확장 보류

다음은 핵심 루프와 온라인 품질이 확인된 뒤 별도 범위로 결정한다.

- 추가 영웅 대량 제작.
- 두 번째 맵.
- 공개 매칭·랭크.
- 스킨·배틀패스·계정 성장.
- 다른 플랫폼.

현재 우선 목표는 **고지 XP→지원 판단→병력과 공성**이 한 판에서 반복되는 선택이 되도록 만드는 것이다.

## 5. 완료 기록 규칙

각 단계는 다음을 남긴다.

- 작업 ID와 변경 이유.
- 구현 commit·엔진·빌드.
- 자동 검사 수와 실패.
- 실제 Windows/사람/온라인 수행 여부.
- 남은 한계와 다음 비교 변수.

수치 변경은 관련 문서·권한 데이터·경계 테스트를 함께 수정하며, 한 비교에서 여러 변수를 동시에 바꾸지 않는다.
