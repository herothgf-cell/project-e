# 개발 로드맵과 진행 게이트

- 원칙: 로컬 실행, 자동 검증, 사람의 게임성 검증, 온라인 품질, 출시 준비를 별도 게이트로 관리한다.
- 관련: [초기 로드맵](../../docs/02-development-roadmap.md), [검증 매트릭스](09-verification.md), [기술 계획](../../docs/technical/02-architecture-and-networking.md).
- 출시일·인원·예산은 확정하지 않는다.
- 2026-10-27 갱신: R24 셀 XP20/30/40, R25 시야원·관측 영역 표시, R26 포탑8.5m, R27 A 공격 이동과 R01/R02/R04를 구현했다. R03의 패키지/실제 PC, R05의 실제 사람 관찰은 [남은 개발 사항](11-remaining-development.md)에서 수행 범위를 나누어 관리한다.

- 이번 경제 묶음: **R09 기지 상점·소모품 전체와 R10의 구매/사용 판단만 구현·자동 검증을 완료했다**. G 성장/B 기지 이동/P 상점/D 사용을 유지하고, 새 전술·설정 저장·온라인 범위로 확장하지 않는다. [확정 설계](../../docs/plans/2026-10-27-base-consumables-design.md)와 [상세 상태](11-remaining-development.md)를 따른다.

- 참고 요청 후 권장 순서: [맵·XP·탑·스킬·속도 재정리](14-tempest-reference-reprioritization.md)에 따라 입력/보상 피드백 → 한 구역 고저차 규칙 → 타워·XP·지원 동선 배치 → 봇 대응과 템포 비교를 제안한다. 신규 R28–R32는 미구현이며 제공 영상의 실제 장면은 접근 제한으로 미확인이다. 현행 코드 감사와 새 제안을 원작 관찰 사실로 혼합하지 않는다.

## 1. 현재 작업의 완료 단위

기존 이동 진단을 M01·세 영웅·기본 공격·전체 기술·봇 교전·성장·공성·승패가 연결되는 로컬 실행판으로 확장했고, 이번에는 직접 시험할 다음 조작·시야·보상·배포 기능을 더했다. 기존 M0 기반과 바스 이동 진단을 보존한다. 초기 로드맵의 온라인 M2 전체 완료로 재분류하지 않는다.

| 묶음 | 산출물 | 통과 기준 | 상태 |
|---|---|---|---|
| 로컬 전투 규칙 | 독립 시뮬레이션, 3영웅, 유효 명령 | 피해·비용·장치·제어·사망 경계 자동 확인 | 전투 규칙 115개 검사 통과; 사람 조작감은 미검증 |
| 로컬 한 판 | M01·웨이브·봇·성장·공성·종료 | 전진과 구조물 압박 유지, 승패/재시작 재현 | 경기 검사1,924개 통과, 새 수치의 6봇 자연 경기27:18 종료; 사람 경기 미검증 |
| 조작과 표시 | 선택·조준·성장·미니맵·결과 | 실제 상태 표시, UI 클릭 관통 없음 | 기존 장면96개 및 새 입력·시야·형상 회귀; 최종 화면과 성능 수정 증거는 검증 문서 참조 |
| 기지 경제 연결 | 구매·재고·선택·D·지속 회복/중단, 같은 API를 쓰는 봇 | 권한 경계·실제 장면 입력·봇 소비·720p/1080p 렌더·새 Windows export | 구현·자동 검증 완료:12묶음3,453 assertion·메인90프레임 통과. 최종 화면/새 export 상태는 [최신 검증](13-consumables-verification.md) 참조 |
| 콘텐츠 문서 | `doc/design` 요소별 규격과 [세 영웅 시트](characters/README.md) | 정본 수치·코드 차이·검증 상태 추적 | 규격 작성·소스 대조; 실행 증거는 검증 문서에 별도 기록 |
| 게임·캐릭터 시안 | [목표 시각 이미지 2종](07-art-direction.md) | 실제 실행 화면과 성격 구분 | 파일 제공; 최종 에셋 제작은 후속 |

위 전투115개·경기1,924개·장면96개와27:18 봇 경기는 이전 회차 증거다. 소모품 추가 후의 새 통합 검사나 자연 경기 결과로 재사용하지 않는다. 이번에는12묶음3,453 assertion 실패0, 별도 장시간 경기1,922 assertion 실패0을 확인했다. 실제 핵 파괴는431.8초(약7분12초) 서쪽 승리였다. 이전27:18 동쪽 승리와 큰 차이는 한6봇 조건의 관찰이며 사람 경기 시간·균형을 입증하지 않는다. [최신 증거](13-consumables-verification.md)를 함께 본다.

## 2. 이후 순서

아래는 장기 제품 단계다. 현재 로컬 개선의 구체적인 다음 묶음은 [R28–R32 권장 순서](11-remaining-development.md#81-참고-요청에-따른-로컬-개발-우선순위권장안)를 함께 따른다. 입력/보상 표시와 작은 공간 실험은 실제 사람 관찰을 준비하면서 진행할 수 있다. 영상 장면이 확보되면 새 지형·XP·스킬 가설을 재검토한다.

| 단계 | 먼저 해결할 질문 | 제작 범위 | 통과 증거 |
|---|---|---|---|
| A. 로컬 안정화와 요청 기능 | 전투 규칙과 화면이 같은 결과를 보여 주고 새 조작/규칙으로 Windows에서 실행되는가? | R01–R05와 R24–R27: 결함 수정, 셀 XP 다양화, 시야원·관측 영역 표시, 포탑 사거리 축소, A 공격 이동, Windows 테스트 패키지 | 확정된 기획, 자동 회귀·실제 프레임, 독립 코드 검토와 Windows/사람 실행 |
| B. 사람의 조작·이해 | 이동·기술·성장·공성 이유를 스스로 설명하는가? | 짧은 튜토리얼, 패시브 HUD, 키/접근성 설정, 기지 상점·선택/D의 이해 | 참가자 수·숙련도·실패 입력·영상 기록 |
| C. 2클라이언트 진단→6인 비공개 온라인 | 지연에서도 명중과 제어를 신뢰할 수 있는가? | 작은 서버 판정/예측·보정 진단 후 전체 상태 복제, 방/버전, 연결·복귀 | 2클라이언트 진단과 6인 세션을 각각 기록, 50/100/150ms RTT, 손실·호스트 종료 |
| D. 균형과 콘텐츠 | 지원·성장·공성에 반복되는 의미 있는 선택이 있는가? | 소모품의 사람 선택 검증, 남은 봇 전술, 선택한 영웅 확장 | 조합·시작 진영·라인별 충분한 사람 경기 |
| E. 출시 후보 | 품질·운영·배포가 함께 준비되었는가? | Windows 배포 최종 검수, Steam, 완성 아트/소리·현지화·설정 | 대상 PC 측정, 패키징·업데이트·설치/실행 검수 |

작은 2클라이언트 진단은 B의 모든 학습·설정 작업 완료를 기다리지 않고 초기 로컬 개선과 병행한다. 경제·봇·표현은 관측된 문제에 맞춰 작은 묶음으로 개선하고, 최종 자산이나 추가 영웅을 크게 늘리기 전에 온라인 판정·보정의 기술 위험을 확인한다. Windows의 첫 독립 실행 확인은 A에서, 출시 배포 검수는 E에서 수행한다.

셀20/30/40 XP·대칭 배치, 포탑9.0→8.5m, 시야원·관측 음영, A 공격 이동이 연결된 상태에서 실제 Windows PC와 사람 플레이를 확인한다. 시야 표시와 효과 렌더의 프레임 시간도 함께 관찰한다. 이후에는 발견된 조작·경로·경고 문제를 우선 수정하고, 기본 상태/동작 표현과 작은2클라이언트 진단을 준비한다.

비공개 방·Steam 연동·공개 매칭은 서로 다른 작업이다. 소수 동시 접속자에게 맞는 운영을 검증하기 전 공개 매칭을 필수로 늘리지 않는다. 현재 실행판에 가짜 온라인 버튼을 두지 않는다.

## 3. 우선 검증할 게임성

| 질문 | 관측 방법 | 다음 조정 |
|---|---|---|
| 바스의 짧은 진입에 대응 가능한가? | E를 본 뒤 회피/반격 성공, 진입 뒤 사망 원인 | 도착 거리·후딜·경고를 먼저 조정 |
| 리오의 두 경로가 읽히는가? | 출발/귀환별 적중·회피, W 목적지 이해 | 선 방향·정지 구간·폭을 먼저 조정 |
| 네마의 핀을 상대가 인식하고 공격하는가? | 핀 생존 시간·파괴 횟수·W/R 취소 원인 | 장치 HP/수명 표시·배치·경고 확인 |
| 인접 지원이 항상 이득인가? | 지원 시간, 비운 라인 XP·타워 손실 | 연결로·보상·병력 압박을 함께 조정 |
| 성장 선택이 구별되는가? | 실제 투자 분포·생존/에너지/공성 변화 | 자동 성장과 투자 효과를 분리해 검토 |
| 기지 구매와 회복 선택이 읽히는가? | B/P 차이·종류 슬롯 선택·빈 재고/D 실패·패치 중단 이해와 사용 시점 | 가격·회복량보다 먼저 안내·클릭·실패 원인을 검토 |
| 12–18분이 적절한가? | 실제 사람 경기 길이와 종료 원인 | 시간이 아닌 압박·복귀·공성 기회를 검토 |

봇 경기 하나의 종료 시간이나 작은 표본의 승률로 위 항목을 통과 처리하지 않는다. 세 영웅이 양 팀에 모두 등장하는 현재 로스터에서는 영웅 승률 단독 지표가 특히 약하다.

## 4. 확장을 미루는 조건

6인 기술 가독성, M01의 안정적인 길찾기, 장치 수명·중단 판정, 성장과 공성의 이해가 해결되기 전 두 번째 맵과 스킨 제작을 늘리지 않는다. 기존 [추가 로스터 후보](../../docs/characters/04-roster-expansion.md)는 개념 검토이며 구현 약속이 아니다.

수치 변경에는 빌드·변경 이유·문서/데이터·회귀 테스트를 함께 남긴다. 다음 작업은 [차이 기록](10-differences.md)의 미구현 항목과 [검증 매트릭스](09-verification.md)의 실패/미검증 항목에서 선정한다.
