## 3. 현재 검증 근거와 한계

[Godot regression #35](https://github.com/herothgf-cell/project-e/actions/runs/40821728887)은 Godot 4.7.2에서 다음을 통과했다.

- 기존 14묶음 3,531개 검사.
- 신규 XP 피드백 88개, 실제 HUD 막대 14개 검사.
- 총 **16묶음, 3,633개 검사, 실패 0**.
- 프로젝트 import와 메인 장면 90프레임 시작.
- 게임 엔진 `ERROR:`·`SCRIPT ERROR:` 없음.

720p·1080p는 headless 엔진에서 실제 컨트롤 경계·겹침·모달 순서를 확인한 결과다. 화면 캡처·Windows 사람 검수는 하지 않았다. 자동6봇 진단은431.8초에 서쪽 팀 승리로 끝났지만, 현행 봇이 XP 셀을 전략 목표로 삼지 않으므로 R30 지원 경사의 재미·균형 증거가 아니다. 실제 Windows PC·사람 경기·온라인 세션은 별도 미검증 상태다.

## 4. 바로 다음 개발 권장 순서

### R29 — 구현 완료, 사람 관찰 대기

셀 값과30/45초 주기를 유지하며 생성 → 실제 개인 지급 → 레벨업/성장 안내를 연결했다. 시야·분수 공유·레벨 상한·중복·일시정지·재시작과 HUD 입력 경계를 검사했다. 다음 사람 플레이에서는 “왜 얼마를 받았고 언제 성장했는지” 이해하는지와 안내 빈도를 확인한다. [검증 기록](17-xp-feedback-verification.md)

### 1순위 — R10 셀·지원 봇 판단

기존 소모품 판단을 유지하고 전술 정책을 다음 순서로 확장한다.

1. 핵 위험과 비어 있는 라인 방어.
2. 가까운 아군 교전 지원 후 원래 라인 복귀.
3. 보이는 셀 가치·거리·라인 손실로 획득/포기 판단.
4. 적 네마 핀 대응.
5. 조작 영웅은 자동 제어하지 않고 숨은 정보는 사용하지 않음.

R30 경사 때문에 셀→연결로 회전이 가능해졌으므로, 셀을 먹은 뒤 영구적으로 라인을 버리지 않는 복귀 조건이 필요하다.

### 2순위 — R31 전투 연결 표현

- 명령 즉시 실행 / 현재 행동 뒤 예약 / 거절을 구분.
- 기본 공격 준비·발사, 기술 선딜·활성·후딜 표시.
- 기절·속박·강화 공격·타워 표적 가독성.
- 선택적 빠른 시전은 한 영웅부터 비교하고 기본값으로 확정하지 않음.

수치 일괄 단축보다 “정상 예약을 입력 씹힘으로 느끼는 문제”를 먼저 분리한다.

### 3순위 — R32 사람 템포 비교

같은 빌드·영웅·진영을 기록하고 다음 사건을 분리한다.

- 입력→접수/예약/발동/다음 행동.
- 라인→고지40XP→지원 연결로→교전 합류→복귀.
- 첫 셀·레벨3/R·첫 탑·핵 노출·종료.
- 회복/귀환/사망 후 다음 전투 기여.

한 봇 경기나 단일 종료 시간으로 이동속도·쿨타임·부활·웨이브를 동시에 바꾸지 않는다.

### 병행 — R03 실제 PC와 R12 소형 온라인 진단

- 최신 R28/R30/R29 소스로 Windows release ZIP 재생성.
- 실제 Windows에서 실행·Alt-Tab·100/150/200% 배율·재시작·로그 확인.
- 작은2클라이언트 장면에서 이동·평타·바스E 권한/보정/중복 효과 확인.

## 6. 완료 기록 원칙

각 작업은 다음을 함께 남긴다.

- 변경 이유와 ID.
- 구현 commit과 사용 엔진/빌드.
- 자동 검사 명령·수·실패.
- 실제 Windows/사람/온라인 수행 여부.
- 남은 한계와 다음 비교 변수.

코드가 존재한다는 사실만으로 재미·균형·성능·온라인 품질을 완료 처리하지 않는다.
