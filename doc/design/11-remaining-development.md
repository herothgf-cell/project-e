# 남은 개발 사항과 추천 순서

- 정리일: 2026-10-26, Asia/Seoul.
- 구현 기준: [a72f5b2](https://github.com/herothgf-cell/project-e/commit/a72f5b2984d026f2a8eff209bbc6c43464efb6f7)의 소스·기획·실행 기록 대조.
- 목적: 현재 완성 범위, 남은 기능, 검증할 가설, 다음 작업의 완료 기준을 한곳에서 관리한다.
- 아래 순서는 이번 검토의 **추천안**이다. 작업량이나 출시일을 확정한 계획은 아니다. 이 문서의 미완료 체크박스는 실제 구현과 완료 증거가 갖춰졌을 때 갱신한다.

## 1. 현재 도달한 단계

**맵 1개와 세 영웅으로 오프라인 3대3 한 판이 진행되는 프로토타입**이다. 전투·성장·공성·승패의 연결은 구현되어 있다. 사람의 조작감·게임성, 독립 Windows 빌드, 온라인 대전과 출시 품질은 별도 확인이 필요하다.

| 영역 | 확보된 상태 | 남은 핵심 |
|---|---|---|
| 전장과 경기 | M01 세 라인, 병력, 탑 12개·핵 2개, 승패·재시작 | 사람의 길찾기·지원·공성 사용성, 경기 흐름 검증 |
| 세 영웅 | 바스·리오·네마의 기본 공격·패시브·Q/W/E/R | 상대법 가독성, 입력 감각, 사람 밸런스 |
| 전투 표시·입력 | 조준·상태·시야·미니맵, 네마 연결·리오 회수점/귀환 경로 | 겹친 대상 선택, 벽 주변 원형·부채 경고, 상태 표현 |
| 성장·경제 | XP·레벨·포인트·R·크레딧 지급·기지 회복 | 상점·소모품·구매/사용 UI, 성장 선택의 체감 |
| 봇 | 라인 전진·교전·공성·퇴각/회복·자동 성장 | 핵 방어, 인접 지원, 라인 전환, 셀·핀 대응, 난이도 |
| 학습·설정 | 영웅 선택, 조작 설명, L3/R 기술 체험 | 단계별 훈련, 연습 초기화, 키/화면/소리 설정 저장 |
| 실행·배포 | Windows export preset, Linux 자동 검사·실제 렌더 기록 | 실제 Windows export와 에디터 없는 PC 실행, 전달 패키지 |
| 온라인·Steam | 설계 문서와 로컬 규칙/표시 분리 | 전송·서버 판정·복제·접속/복귀·Steam 연결·배포 |
| 아트·음향 | 임시 3D 형상, 콘셉트 이미지 2종 | 게임용 모델·동작·아이콘·VFX·효과음·음악 |

기존 검증은 5개 묶음의 **2,192개 assertion 통과**, 메인 장면 시작, 실제 렌더 8프레임이다. 6봇 일반 경기는 **20분 11초에 실제 핵 파괴로 종료**했다. 이는 한 조건의 자동 경기 결과다. 사람 1명+봇 5명과 사람 6명의 경기 시간·재미까지 검증한 결과는 아니다. 근거는 [검증 기록](09-verification.md)과 원문 로그에 있다.

이미 수정한 예약 명령 교체, 네마 지속 연결, 리오 회수점·귀환 경로, 적 선 효과의 시야 제한은 새 미구현 목록에 다시 넣지 않는다. 현재 1m 길찾기 격자는 구현 방식의 한계이며, 확인하지 않은 모든 경로를 결함으로 분류하지 않는다. 근거: [구현 차이](10-differences.md).

## 2. 바로 다음 개발 묶음 — 사람이 직접 시험할 수 있는 버전

다음 한 묶음의 목표는 **게임을 내려받아 실행하고, 자신의 조작과 전투 결과를 이해하면서 한 판을 끝내는 것**이다. 최근 Godot 실행 파일을 찾는 과정의 불편도 고려해 독립 Windows 테스트 빌드를 우선 배치한다.

|---|---|---|---|

실행 체크리스트:

- [ ] R01 — 표적 우선순위 수정과 회귀 확인.
- [ ] R02 — 벽 주변 경고 형상 수정과 실제 프레임 확인.
- [ ] R03 — Windows 패키지 제작 및 실제 Windows 실행 확인.
- [ ] R04 — 최소 안내 보완과 첫 플레이 관찰 준비.
- [ ] R05 — 실제 사람 경기 기록과 후속 수정 우선순위 갱신.

R01·R02는 [현재 차이](10-differences.md)의 구체적인 후속 과제다. R03은 [빠른 시작](../../docs/technical/03-godot-quickstart.md)의 미완료 검증을 해결한다. R04·R05는 [사람 플레이 절차](09-verification.md)와 [학습 설계](../../docs/content/04-modes-onboarding-and-ui.md)에 연결한다.

## 3. 전투·학습·경제 완성

다음 작업은 첫 사람 테스트에서 발견한 문제를 근거로 작은 묶음으로 진행한다. 최소한의 전투 동작·핵심 효과음은 초기에 넣고, 출시용 모델과 전체 음원 제작은 별도 단계로 관리한다.

| ID | 남은 작업 | 현재와의 차이 | 완료 기준 / 선행 관계 |
|---|---|---|---|
| R06 | 공격·시전·피격·제어 상태의 표현 | 현재 모델은 회전·이동 흔들림이 중심이며 패시브는 문자 HUD로 안내 | 기본 공격, 시전 준비/후딜, 기절/속박, 강화 공격, 탑의 공격 대상을 구분한다. 간단한 자세·상태 아이콘·핵심 소리로 먼저 확인하고 실제 판정 시간과 맞춘다. |
| R07 | 연습장과 단계별 튜토리얼 | L3/R 기술 체험과 전체 학습 기능은 다름 | 레벨·성장·쿨타임 초기화와 정지/이동 타깃을 제공한다. 이동→기술→성장→지원→공성 과제를 다시 시도/건너뛸 수 있다. 소모품 과제는 R09 이후 연결한다. |
| R08 | 입력·카메라·화면·소리 설정 | 주요 키는 고정 분기이며 사용자 설정 저장이 없음 | 키 충돌/복원, 카메라 동작, 창/전체화면, UI 크기와 음량을 설정하고 재실행 후 유지한다. 우선 확인할 해상도는 1280×720·1920×1080, Windows 배율은 100/150/200%로 제안한다. |

| R11 | 경기 흐름·성장 선택·결과 피드백 | 자연 종료와 기본 결과 화면은 있으나 사람의 선택 효과는 미검증 | 첫 교전·첫 탑·핵 노출·종료, 지원 비용, 투자, 복귀 이유를 기록한다. 킬 외 공성·보호·지원 기여를 결과에서 이해할 수 있게 확장한다. 작은 관찰 기록부터 시작하고 필요한 경기 로그 저장을 보강한다. |

소모품은 이미 정해 둔 [성장·경제](05-growth-and-economy.md)의 최소 범위를 사용한다. 에너지 병은 40크레딧/2초간 에너지40, 수리 패치는 50크레딧/4초간 HP200이며 적 영웅 귀속 피해로 중단된다. 합산 2개 보유와 공유 12초 사용 쿨타임, 기지 구매 조건을 함께 구현한다. 이 과제를 장비 조합이나 계정 재화 추가로 확장하지 않는다.

경기 시간 목표의 기준은 [사람 6인 정상 경기의 중앙값 12–18분](../../docs/04-playtest-and-balance.md)이라는 가설이다. 6봇 한 경기의 20:11만으로 특정 영웅을 하향하거나 핵 HP를 줄이지 않는다. 복귀·이동·부활·병력 보호 중 지연 원인을 확인하고 한 번에 바꾸는 변수를 제한한다. 현재 각 팀에 세 영웅이 모두 들어가므로 영웅 승률만으로 균형을 판단하기도 어렵다.

## 4. 온라인 — 초기부터 작은 진단을 병행

**R12의 2클라이언트 진단은 R06–R11을 전부 마친 뒤까지 미루지 않는다.** Windows 실행 기반과 기본 명령 경계가 준비되면 로컬 개선과 같은 초기 개발 구간에 착수한다. 실제 작업 순서는 같은 사람이 맡는 역할과 가용 시간에 맞춘다.

| ID | 남은 작업 | 범위 | 완료 기준 / 의존성 |
|---|---|---|---|
| R12 | 2클라이언트 서버 판정 진단 | 작은 장면에서 바스 이동·기본 공격·E부터 시작하고 나머지 판정으로 확장 | 두 독립 실행 클라이언트가 같은 서버 결과를 본다. 입력 소유권·번호·자원 검증, 상태 전송, 자기 이동의 예측/보정, 원격 유닛 보간과 중복 효과 방지를 확인한다. RTT 50/100/150ms·손실 조건과 호스트 역할 교대를 기록한다. |
| R13 | 전체 3라인·3영웅·6클라이언트 동기화 | R12 통과 후 병력·구조물·장치·성장·보상·승패를 확장 | 숨은 적 상태의 전송 범위를 제한한다. 리오 왕복, 네마 핀 제거, 사망/부활, 동시 핵 파괴가 일치하며 중복 피해/소비/보상이 없다. 현재 팀0 고정 표시를 실제 조작 팀 기준으로 일반화한다. |
| R14 | 비공개 방과 온라인 경기 흐름 | 생성/참가→팀/영웅 선택→준비→시작→결과→재경기 | 버전 차이·가득 찬 방·참가 실패·호스트 종료를 구별한다. 온라인 성장 패널은 경기 전체를 멈추지 않게 설계한다. 팀 상태와 지원/공격/후퇴 핑도 실제 전송 규칙과 연결한다. |
| R15 | 연결 손실·봇 인계·재접속 | 문서의 5초 인계/60초 복귀는 초기 정책 | 한 영웅을 사람과 봇이 동시에 제어하지 않는다. HP·쿨타임·성장·부활 시각을 복원한다. 호스트 종료는 세션 중단으로 안내하고 승패를 만들어내지 않는다. |

현재 구현은 로컬 시뮬레이션이다. 규칙과 표시를 분리했다는 사실만으로 전송·예측·보정이 구현된 것은 아니다. 네트워크 기술 선택과 자세한 계약은 [기존 아키텍처 계획](../../docs/technical/02-architecture-and-networking.md)을 따른다. ENet/RPC 직접 연결 진단과 Steam 초대/전송 경로는 각각 검증한다.

초기 조사값인 입력 반응·이동 보정 거리·30Hz 서버 주기와 이후 60fps 목표를 이미 달성한 성능으로 쓰지 않는다. 실제 6인 경기를 확보한 뒤 세 라인의 지원·성장·공성, 진영과 조합의 영향을 다시 평가한다.

|---|---|---|
| R16 | 콘셉트에서 실제 게임용 자산으로 제작 | 영웅 1종과 맵 한 구역의 모델·재질·리그·동작을 먼저 검증한다. 게임 카메라에서 아군/적과 위험을 읽을 수 있으면 세 영웅·병력·탑·핵·셀로 확대한다. 생성 시안을 완성 모델로 계산하지 않는다. |
| R17 | UI 아이콘·효과·음향 완성 | 패시브/12개 액티브 아이콘, 시전 전/활성/적중/종료, 공격·실패·핵 노출 소리를 구분한다. 시야 밖 적중 정보가 소리나 숫자로 노출되지 않아야 한다. 음악과 환경음은 전투 경고를 가리지 않는다. |
| R18 | 대상 PC 성능·장시간 안정성 | 실제 Windows 장비에서 교전·병력·장치 중첩과 반복 재경기를 측정한다. 프레임 시간, 메모리/객체 잔류, 서버 tick·전송량의 분포를 기록하고 확인한 최소 사양을 정한다. |
| R19 | 접근성·현지화·최종 화면 검수 | 색상 외 형태·윤곽, 글자/UI 크기, 번쩍임/흔들림 옵션, 설정 저장, 확정한 지원 언어를 확인한다. 다양한 화면 비율·Windows 배율에서 필수 정보와 버튼이 유지된다. |
| R20 | 빌드 자동화·버전·진단·업데이트 | R03에서 시작한 절차를 반복 가능하게 만든다. commit·엔진/templates·콘텐츠/프로토콜 버전과 산출물을 연결하고 검사→export→패키징 기록을 남긴다. 설치/재실행/업데이트 실패와 이전 빌드 복구도 확인한다. |

아트와 음향의 제작 단위는 [현재 아트 방향](07-art-direction.md)과 [콘텐츠 제작량](../../docs/03-content-matrix.md)을 따른다. 최종 모델 확대는 전투 타이밍과 기본 가독성이 안정된 뒤 진행한다. R18의 실제 PC 측정은 초기 Windows 테스트부터 누적하고 출시 직전에만 시작하지 않는다.

## 7. 검증 후 결정할 확장

| 후보 | 착수 조건 | 현재 판단 |
|---|---|---|
| 오린·테르·무아 등 추가 영웅 | 초기 세 영웅의 실제 상대법·학습·6인 교전에서 부족한 선택을 확인 | 개념 후보다. [확장 기획](../../docs/characters/04-roster-expansion.md)에 따라 필요한 한 명부터 상세 설계한다. |
| 공개 매칭 | 지역·시간대별 실제 접속자와 경기 성립률·대기 시간·실패율 확보 | 비공개 방과 외부 테스트 뒤 제공 여부를 결정한다. |
| 두 번째 맵·랭크·스킨·배틀패스·계정 성장·다른 플랫폼 | 핵심 제품이 검증되고 별도 목표·제작 범위를 정함 | 현재 다음 개발 묶음에서 보류한다. |

현재의 재미 목표는 **짧은 기술 교환, 세 라인 사이의 지원 판단, 경기 중 성장, 병력을 동반한 공성**이다. 콘텐츠 수를 늘리는 것만으로 이 네 가지를 검증했다고 판단하지 않는다.

## 8. 추천 진행 순서와 단계 종료 기준

| 단계 | 주된 작업 | 함께 준비할 일 | 다음 단계로 넘어갈 근거 |
|---|---|---|---|
| 1. 직접 시험할 수 있는 로컬판 | R01–R05 | 빌드 식별·기본 로그·첫 PC 성능 기록 | Windows에서 실행해 일반 경기와 재시작을 완료하고, 실제 플레이 문제 목록을 확보 |
| 2. 선택과 반응 개선 | R06–R11 중 관측상 우선 과제 | R12의 작은 2클라이언트 진단 | 조작/기술/성장/공성 이유를 설명할 수 있고, 온라인 기본 판정/보정 위험을 확인 |
| 3. 실제 사람 6인 경기 | R13–R15와 균형 재검증 | 검증된 한 영웅/맵 구역의 아트·핵심 소리 | 접속→한 판→결과→재경기가 이어지고 지원·성장·공성에 선택 이유가 나타남 |
| 4. 외부 테스트와 출시 품질 | R16–R23 중 확정한 제품 범위 | 필요성이 확인된 영웅 한 종씩 확장 | 실제 배포/업데이트·지원 PC·운영 방식과 공개 기능이 검증된 출시 후보 |

기간은 각 작업의 실제 소요와 재작업, 주당 가용 시간, 외부 테스트 모집/검수 대기를 기록한 뒤 추정한다. 한 사람의 여러 역할을 병렬 인원 수로 계산하지 않는다.

## 9. 작업 완료 기록 양식

각 항목을 완료 처리할 때 ID, 변경 이유, 구현 commit, 사용 빌드, 자동 검사와 사람/Windows/온라인 확인 결과, 남은 한계를 함께 남긴다. 코드가 들어간 것과 사람이 확인한 결과를 별도 상태로 기록한다.

이번 정리는 문서와 소스의 읽기 대조다. 게임 기능이나 전투 수치를 변경하지 않았으며, 위 2,192개 검사와 봇 경기 결과는 기준 구현의 [기존 실행 증거](09-verification.md)를 인용했다. 이후 변경에는 그 변경의 위험을 확인할 검사와 실제 플레이 증거를 추가한다.
