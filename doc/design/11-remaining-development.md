# 11. 남은 개발 — V5 복구 이후

- 기준일: 2026-11-05.
- 현재 실행 상태와 자산: [V5 안내](25-illustrated-canal.md).
- 실제 수행된 검사·렌더·배포 확인: [V5 검증 기록](verification/2026-11-05-v5-verification.md).

## 1. 현재 출발점

세 라인과 공성, 바스·리오·네마의 기본 공격·패시브·Q/W/E/R, 성장·상점·소모품, 시야·고지, 사람 1명과 봇 5명의 오프라인 경기가 구현되어 있다. 봇은 관측한 셀 수집, 지원·핵 방어·기지 복귀와 소모품을 사용한다. F6 전장 보기와 별도 상태의 F7 검토실도 존재한다.

V5는 얼굴·의상 텍스처가 있는 3등신 영웅 GLB, 수로와 건축물, 현재 초상화를 복구한 단계다. 영웅당 10개 관절 클립과 12개 영웅별 Q/W/E/R 동작, 스킬 효과와 전투 음향이 실행판에 연결되어 있다. 이를 ‘봇·애니메이션·음향을 처음부터 구현해야 하는 단계’로 되돌리지 않는다.

이번 자동 검사와 실제 렌더의 수행 결과는 검증 문서에 기록한다. 스크립트로 구성한 교전, 검토실 재생, 봇 경기와 패키지 실행은 각각 다른 증거다. **Windows 사용자 PC 수동 플레이, 사람 간 경기 밸런스, 온라인·Steam은 아직 검증되지 않았다.**

## 2. 바로 이어서 할 일

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| 1 | Windows 사용자 PC에서 첫 실행과 한 경기 확인 | 배포본 시작, 영웅 선택, 이동·공격·Q/W/E/R, 상점, 사망·부활, 승패와 재시작을 실제 입력으로 확인하고 환경·문제를 기록 |
| 2 | 실제 경기 가독성 평가 | 세 라인 이동·고지 진입·6영웅 교전에서 대상·위험 범위·팀·체력·조준이 읽히는지 기록하고 우선순위대로 수정 |
| 3 | V5 자산과 동작 정리 | 얼굴·의상/초상화의 일치, 관절 벌어짐·무기 관통·발 접지·피격 강도를 점검하고 검토실·실제 전투에서 재확인 |
| 4 | 실기 성능 측정과 최적화 | 대상 PC의 해상도·설정·CPU/GPU를 기록하고 교전·전장 보기의 프레임 시간, 드로콜·메모리를 측정한 뒤 비용이 큰 부분을 개선 |
| 5 | 사람 플레이를 바탕으로 경기 흐름 조정 | 성장 속도·셀 경쟁·고지 회전·공성·종료 시간을 관찰하고 변경 수치와 이유를 별도 기록 |

우선순위는 실행 가능한 통합판을 유지하면서 피드백을 반영하는 것이다. 미술 조정을 이유로 전투 수치나 타격 판정을 함께 바꾸지 않는다. 수치 변경이 필요하면 목표와 비교 조건을 먼저 남긴다.

## 3. 기능별 후속 범위

| 영역 | 현재 확보 | 남은 작업 |
|---|---|---|
| 전투 입력 | 대상 선택, 공격 이동, 조준과 벽에 맞춘 경고 | 복잡한 겹침 상황, 오입력·취소 피드백, 키 재지정과 접근성 |
| 경기·경제 | 성장·R 해금·셀 보상·상점·소모품 | 사람 경기의 가격·회복량·성장 속도·종료 시간 검토 |
| 봇 | 라인 전투, 관측 셀, 지원·핵 방어·복귀, 성장·소모품 | 전역 빈 라인 판단, 적 설치물 우선순위, 팀 공성 조율, 난이도 차이 |
| 고지·동선 | 고지 2곳, 경사로 4개, 높이·시야·이동 판정 | 실제 플레이의 진입 인지와 회전 선택 검토, 장식 가림 개선 |
| 캐릭터 | 텍스처 GLB 3종, 관절 동작 30개, 12개 Q/W/E/R 표현 | 발 접지·무게·의상 움직임의 자연스러움, 편집 원본과 제작 절차 정리 |
| 이펙트·음향 | 전투 상태에 연결된 스킬 효과와 WAV 5개 | 교전 중 겹침·음량·반복 피로도와 사용자 설정 |
| UI·도움말 | 성장·상점·도움말·미니맵·검토실 | 해상도·글자 크기·대비·튜토리얼·설정 저장 |
| 배포 | Godot 내보내기·패키징 경로와 자동 검사 | 대상 Windows PC의 실행·권한·입력·오디오·실기 성능 확인 |
| 온라인 | 로컬 전투 상태를 중심으로 구현 | 2인 연결 실험, 권한·동기화·지연 처리, 6인 확장·재접속·로비 |
| Steam | 후속 배포 계획 | 실제 연동·초대·배포 절차와 검증 |

원본 V5 모델을 정확히 다시 만드는 생성기는 현재 회수되지 않았다. 이전의 텍스처 없는 생성기는 현행 모델을 대체할 수 없다. 당장은 최종 GLB와 WebP를 보존하고 관절 이름·피벗 계약을 지키며 편집한다. 자세한 제한은 [V5 모델 수정](25-illustrated-canal.md#5-모델과-텍스처-수정-계약)을 따른다.

## 4. 단계 완료를 판단하는 증거

자동 검사는 판정과 회귀를 확인하고, 실제 렌더는 자산 연결·동작·표시를 확인한다. 봇 장시간 경기는 종료 가능성과 상태 흐름을 확인하며, 사람 플레이는 조작 이해·가독성·재미·밸런스 판단에 필요하다. 내보내기 성공과 Linux 환경에서의 패키지 렌더 확인만으로 Windows 사용자 PC의 수동 플레이를 완료 처리하지 않는다.

이전 R 단계 및 V2·V3·V4 검증 기록과 스크린샷은 [설계 목차](README.md)에 보존한다. 과거 검사 개수, 단일 봇 경기 시간, 소프트웨어 렌더러의 화면 카운터는 이번 버전의 성능·사람 경기 목표를 보증하는 숫자로 재사용하지 않는다.
