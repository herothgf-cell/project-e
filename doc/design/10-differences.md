# 기존 설계와 현재 실행판의 차이

- 기준일: 2026-10-26.
- 목적: 기존 제안, 이번 결정, 현재 구현 한계를 구별해 다음 작업에서 잘못된 전제를 쓰지 않게 한다.
- 기존 `docs`를 삭제하거나 구현 차이에 맞춰 조용히 고쳐 쓰지 않는다. 새 콘텐츠의 현재 안내는 [이 문서 묶음](README.md)을 따른다.

## 1. 의도적으로 정한 차이

| ID | 기존 제안 | 이번 결정 | 이유/후속 |
|---|---|---|---|
| D01 | 새 문서 `docs` 배치 | 새 콘텐츠별 기획은 `doc/design` | 사용자의 최신 경로 요청 |
| D02 | 6명 사람/봇 혼합·비공개 온라인 | 한 로컬 사람+봇 5명 | 전장·세 영웅·한 판 루프를 먼저 플레이 |
| D03 | 선택 60초·준비 15초 | 메뉴 선택 후 즉시 시작 | 로컬 반복 실행을 간단히 함; 온라인 동기화는 후속 |
| D04 | 정상 레벨 1·2포인트 | 정상 유지, 별도 기술 체험에서 여섯 영웅 모두 L3·R 해금·잔여 3점 | 모든 기술을 빠르게 확인하되 연습 조건 표시 |
| D05 | U 성장/G 핑/B 상점 | G 성장/B 기지 이동 | 현재 제공하는 행동을 단축키에 직접 배정 |
| D06 | D 소모품·기지 구매 | 이번 범위에 상점·D 없음 | 성장·회복·공성을 먼저 연결; 품목 수치는 보존 |
| D07 | 최종 권한 서버·30Hz 온라인 | 30Hz 로컬 시뮬레이션 | 규칙/표시 분리만 준비; 인터넷 서버 구현 아님 |
| D08 | 출시용 3D·애니메이션·음향 | 식별 가능한 임시 3D와 별도의 생성 시안 | 실행 판정 검증과 미술 목표 제안의 역할 구별 |
| D09 | 전투 중에도 성장 입력 가능 | 성장 패널을 여는 동안 로컬 시뮬레이션 일시정지 | 투자 항목을 읽는 편의; 온라인 시간 진행 정책과 구별 |

## 2. 구현 대조 기록

2026-10-26 소스를 읽어 확인한 범위다. ‘코드 반영’은 아래 연결된 파일에 규칙 분기와 수치가 있음을 뜻하며, 테스트·장시간 경기·실제 화면의 통과 기록은 [검증 매트릭스](09-verification.md)에서 별도로 확인한다.

| 영역 | 대조 상태 | 실제 근거와 범위 |
|---|---|---|
| 기본 공격·상태·보호막 | 코드 반영 | [경기 상태](../../game/project-e/scripts/battle/battle_state.gd), [공통 판정](../../game/project-e/scripts/battle/battle_rules.gd): 기본값·피해·출처별 보호막·제어·부활 |
| 세 영웅의 기술 | 핵심 수치·기하·단계 코드 대조 | [기술 구현](../../game/project-e/scripts/battle/hero_abilities.gd), [영웅별 대조 표](characters/README.md); 각 시트의 모든 검증 기준이 통과했다는 뜻은 아님 |
| 전장·병력·봇 | 좌표·생성·자동 행동 코드 대조 | [맵](../../game/project-e/scripts/battle/battle_map.gd), [봇](../../game/project-e/scripts/battle/battle_ai.gd); 단순 라인 판단과 전술 난이도 구별 |
| 경제 | 수입·성장 코드 대조, 구매 미구현 | XP·포인트·R·공유 보상·크레딧 수입·기지 회복. 소모품·상점·D 사용은 후속 |
| 시야·UI | 명령 검사와 표시 분기 대조 | [전장 입력](../../game/project-e/scripts/presentation/battlefield.gd), [HUD](../../game/project-e/scripts/presentation/battle_hud.gd); 실제 화면·숨은 정보 경계는 별도 검증 |

## 3. 현재 구현의 한계

| ID | 현재 동작 | 분류와 다음 기준 |
|---|---|---|
| L01 | 원형·부채 경고는 전체 윤곽을 그리지만 실제 효과는 벽 뒤 대상을 제외한다 | 알려진 표시 차이. 판정이 제공한 유효 형상을 표시층이 그리도록 보완하고 벽 모서리 프레임에서 비교 |
| L02 | 길찾기는 1m AStar 격자와 연속 구간 검사를 조합한다 | 구현 방식의 한계. 자유공간 최단 경로나 모든 좁은 모서리 통과를 보장하지 않음; 실제 출발/복귀·타워 접근을 검증 |
| L03 | 봇은 0.4초마다 배정 라인·근처 교전·기지 복귀·자동 성장 판단을 한다. 바스 R은 보이는 영웅 한 명에게도 사용한다 | 프로토타입 범위. 원본 바스 목표의 두 명 이상 R 판단, 난이도별 350/650ms 반응, 전략적 지원/라인 전환, 셀 수집·적 핀 집중 파괴는 후속 |
| L04 | 경고·타격·이동은 30Hz 틱에서 진행한다. 패시브 상태는 문자 HUD로 안내하고 네마 연결선·리오 회수점/귀환 경로는 바닥 형상으로도 표시한다 | 실제 타이밍·가독성 실측 필요. 완성 애니메이션·아이콘·음향·튜토리얼 검증과 구별 |

L01은 적중 규칙을 바꾼 기획 결정이 아니다. 표현과 판정이 다르다는 사실을 남긴 수정 과제다. 새로 발견한 결함도 의도적 축소로 재분류하지 않고 이 표나 실제 검증 기록에서 추적한다.

## 4. 유지하는 기준

M01 좌표, 기본 HP/이동/공격, 에너지, 기술의 핵심 기하·타이밍·비용, 레벨 1–12와 투자 상한, 20초/18초 웨이브, 탑/핵 HP와 공성 보호, 사망·부활 공식은 기존 정본에서 이어받는 기준이다. 소스 대조와 별개로 상세 경계의 동작은 실제 테스트로 확인한다. 편의상 체력을 낮추거나 타워를 처음부터 노출해 끝나는 경기를 일반 규칙으로 쓰지 않는다.

기술 표에서 위력 100으로 계산한 피해 예는 공식 검산이다. 정상 R은 레벨 3부터 열리므로 자동 성장만으로도 위력 106 이상이다. 기술 체험의 표시 피해를 100 기준 예와 직접 비교해 버그로 판단하지 않는다.

## 5. 이 실행판으로 아직 입증하지 않은 것

사람 6명의 재미와 균형, 12–18분 경기 길이, 낮은 지연·패킷 손실에서의 공정성, 재접속, Steam 인증/로비/배포, Windows 내보내기, 특정 하드웨어 60fps, 출시용 아트·음향·접근성은 별도 게이트다. 하나의 기능이 미구현이면 작동하는 메뉴처럼 노출하지 않는다.

차이를 추가할 때는 원래 근거, 현재 실제 동작, 의도적 결정인지 결함인지, 추후 통과 기준을 함께 적는다. ‘간소화’라는 말만으로 알려진 판정 결함을 숨기지 않는다.

## 6. 최종 검토에서 남긴 경미한 입력 차이

겹친 적 클릭은 현재 화면상의 중심 거리로 고른다. 원본의 영웅→병력→공격 가능한 구조물 우선순위를 아직 적용하지 않았고, 잠긴 구조물도 선택 후보에 들어갈 수 있다. 가까운 병력/잠긴 탑이 겹친 영웅보다 먼저 잡힐 수 있으므로 후속 입력 개선에서 우선순위와 잠금 제외를 보완한다. 대상 순환 키의 미구현과 별개로 추적한다.
