# 다음 작업 순서와 완료 판정

정리일 2026-11-19. **아래는 후속 제안**이다. 현재 구현 완료 목록이나 승인된 일정이 아니다. 게임 코드는 V9를 기준으로 보존하며, 새 작업의 기준 커밋과 실제 관측 결과를 기록한다.

## 1. 추천 순서

현재 사용자 불만과 새 환경으로의 이전 목적을 고려하면 **실행 재현 → 조작·전장 체감 → 공성·미니언 → 아트 품질 → 전체 조합·경제 → 온라인·출시** 순서가 적절하다. 이미 구현된 8영웅이나 세로 맵을 처음부터 다시 만드는 작업으로 시작하지 않는다.

| ID·우선순위 | 작업 | 선행 조건 | 산출물 | 완료 판정 |
|---|---|---|---|---|
| H01 · P0 | 새 환경에서 기준 실행 | 전체 소스, 고정 엔진 | 커밋·엔진·OS·해상도·실행 기록 | 선택→일반 경기→결과·재시작, 자산 누락 여부 확인 |
| H02 · P0 | 실제 Windows 조작 확인 | H01 | 조작별 재현·짧은 기록 | 이동·공격·스킬·UI·카메라·Alt-Tab의 실패 여부 설명 |
| H03 · P1 | 맵·카메라 체감 개선 | H02의 관측 | 기존/변경 동일 구도·입력 비교 | 네 방향 이동·추적 복귀·미니맵 입력과 전투 가독성 확보 |
| H04 · P1 | 공성·미니언 후속 실험 | H01, V9 AI 적용 | 통제 조건과 핵별 사건 기록 | 종료 시간뿐 아니라 지연 원인·재정비 기회를 설명 |
| H05 · P1 | 대표 영웅·전장 아트 검토 | H01, 시안·실제 화면 | 얼굴·장비·모션·맵 비교 보드 | 사용자 피드백과 수용·보완 항목 기록 |
| H06 · P2 | 8영웅 학습·대응·조합 | H03~H05 | 기술/1대1/라인/전체 경기 기록 | 각 핵심 연계·상대법이 실행되고 읽힘 |
| H07 · P2 | 성장·골드·소비품 점검 | H06 관측 | 수입·지출·마나 부족·미사용점 분석 | 경제 자원이 교전 선택에 쓰이는지 판단 |
| H08 · P2 | 신규 사용자 학습 | 기존 조작 안정 | 첫 경기 안내·학습 흐름 제안 | 원작을 모르는 사용자가 다음 행동을 설명 |
| H09 · P3 | 온라인 기술 검증 | 전투·입력 기준 안정 | 2클라이언트 진단부터 단계 확장 | 연결·권한·지연·이탈에 대한 실제 기록 |
| H10 · P3 | Steam 제품화 | 온라인·사람 검증과 제작 여건 | 출시 체크·빌드·운영 계획 | 기능·배포·운영 각 단계에서 증거 확보 |

P0/P1은 인수 후 추천 우선순위다. 원본 로드맵의 M0~M6 완료 상태와 자동으로 대응시키지 않는다. 일정과 예산은 이 문서에서 확정하지 않는다.

## 2. 공성·미니언 실험을 시작하는 법

### 기준 조건

- V9 기준 커밋과 실제 전투·관찰기 파일 해시를 남긴다.
- 실제 경기와 같은 TacticalAI를 사용한다. BattleState만 만들고 기본 AI로 측정한 결과를 V9 결과와 섞지 않는다.
- 바스·오린·테르의 기존 세 편성을 먼저 재현할 때는 과거 기록과 같은 조건인지 확인한다.
- 새로운 사람·영웅·진영 조건을 추가하면 별도 표본으로 기록한다.
- 한 번에 주된 가설 하나만 바꾸고, 수치와 AI를 동시에 바꿔 원인을 잃지 않는다.

### 반드시 기록할 지표

| 질문 | 지표 |
|---|---|
| 언제부터 끝날 기회가 있었나 | 각 진영 핵의 노출·첫 피해·파괴 시각 |
| 실제 공격이 왜 끊기나 | 핵별 피해 최대 공백, 영웅·병력 동시 체류 |
| 병력이 공성 기회를 만들었나 | 도착 병력 수·체력·생존·구조물 피해 |
| 초반이 너무 빨라졌나 | 첫 외곽·내곽 파괴, 성장·사망과 복귀 |
| 열세 팀에게 선택이 있나 | 방어·회복·라인 전환·역전 기회 |
| 자동 행동 문제인가 | 재배치·표적 선택·후퇴·진입 이유 |

첫 핵 노출과 실제로 파괴된 다른 핵의 피해·파괴를 같은 대상처럼 계산하지 않는다. 관찰 상한 도달은 미종료로 적고 경기 종료 시간으로 기재하지 않는다.

### 이미 검토된 가설

과거 기록에는 핵 우선 목표, 비가시 핵 접근, 국지 인원 우세 판단, 후반 공성병 빈도 증가, 만렙 셀 선택 차단이 있다. 채택되지 않은 이유와 조건을 [감사](../design/29-cot-map-minion-siege-review.md), [V9 검증](../design/verification/2026-11-10-v9-verification.md)에서 읽는다. 다른 조건으로 다시 검토할 수 있으나 새로운 가설처럼 중복 작업하지 않는다.

## 3. 그래픽과 카메라 검토를 구체화하기

| 분야 | 비교할 자료 | 수정 결정에 쓸 질문 |
|---|---|---|
| 캐릭터 | 시안, 정면·측면·게임 카메라 캡처 | 3등신 비율·얼굴·장비가 같은 인물로 읽히는가 |
| 모션 | 이동·기본공격·QWER의 짧은 실제 영상 | 준비·타격·회복이 보이고 이동 연결이 자연스러운가 |
| 맵 | 전체 지도와 실제 전투 높이의 화면 | 이동 가능 공간·차폐·고지·기지 입구가 읽히는가 |
| 효과 | 다수 영웅 기술이 겹친 실제 화면 | 팀·범위·경고·잔류 효과를 구분할 수 있는가 |
| 카메라 | 같은 입력의 기존/변경 기록 | 의도치 않은 추적 해제·급변·UI 입력 누수가 있는가 |

최신 [D 혼합형 아트 계획](../design/31-subculture-fantasy-hero-art-direction.md)의 A 게이트는 바스·리오·네마·세라의 스타일을 먼저 맞추는 안이다. 이 가운데 대표 영웅과 전장 한 구역을 실제 런타임에서 확인한 뒤 같은 기준을 8명 로스터와 전체 맵에 적용하는 순서를 제안한다. 3~3.5등신 인게임과 6~7등신 선택 일러스트는 별도 산출물이며, 실제 모델·모션을 확인하기 전에 컨셉 이미지만으로 개선 완료를 판정하지 않는다.

## 4. 작업을 맡길 때의 최소 명세

각 작업은 “현상 → 재현 조건 → 현재 코드·자료 → 변경 범위 → 완료 판정 → 결과”를 갖춘다. [요소 기획 템플릿](templates/feature-spec.md)을 복사해 사용한다.

기능 완료 판정은 규칙·입력·표시·상태 종료·예외를 포함한다. 밸런스 변경은 비교 조건과 플레이 판단을 추가한다. 문서 편집만 한 작업에는 게임 실행 성과를 붙이지 않는다.

## 5. 단계별 검증

문서만 변경하면 링크·파일·수치·용어를 검증한다. 전투·AI·입력 코드를 변경하면 관련 동작 회귀를 먼저 확인하고, 배포나 전체 경기 결과에 영향을 주는 변경에서 필요한 전체 검증을 추가한다. 어떤 실행도 실제 수행한 명령·코드·환경·결과로 기록한다.

새 테스트가 필요한지는 변경 위험과 기존 검증의 빈틈으로 판단한다. 기존 구현을 그대로 베끼는 검사나 같은 결과를 의미 없이 반복하는 작업은 완료 조건으로 추가하지 않는다.
