미술 목표는 **3등신의 귀여운 세미 카툰 판타지 영웅, 밝은 수로 공방, 전투 정보 우선**이다.
현재 8명은 무기·머리 장식·색·시전 자세로 역할을 구분한다. [현행 미술 상세](../../design/content/09-art-and-audio.md)

| 날짜 | 전달된 사용자 대화 이력 | 인계에 남길 의미 |
|---|---|---|
| 2026-11-03 | “캐릭터가 3등신 정도로 하고 이 UI 토대로” | 비율과 UI 시안을 함께 반영할 요구 |

위 인용의 출처는 **이번 인계에 전달된 사용자 대화 이력**이며 저장소 문서에서 인용한 문장이 아니다.

“상용 수준 애니메이션 완성”, “시안과 동등한 품질 달성”은 현재 인계의 완료 주장에 포함하지 않는다.

## 3. 영웅별 시각 언어

| 영웅 | 현재 목표 실루엣·소재 | 전투에서 읽혀야 할 행동 |
|---|---|---|
| 바스 | 낮고 큰 건틀릿, 붉은 천·금빛 룬·거석 | 진입, 양손 타격, 룬 축적과 보호 |
| 리오 | 원반·넓은 모자, 보라 천·별빛 | 왕복 궤도, 닻, 귀환 방향 |
| 네마 | 정령 지팡이·잎, 녹색 천·목재 | 정령목 설치·연결·보호 |
| 오린 | 송풍관·두건, 모래색 천·금빛 바람 | 준비 사격과 반동 |
| 테르 | 긴 수정 방패, 빙청색 결정·판 | 후방 보호와 후퇴 반격 |
| 무아 | 붓통·수평 붓, 민트 물결·유약 | 바닥 채색과 활성 구역 전환 |
| 세라 | 양손 초승달 검·짧은 망토 | 짧은 진입, 표식 축적·회수 |
| 루메 | 연금 병·둥근 모자, 주황 불씨·유리 | 투척, 포격 예고와 잔열 |

이 표는 [콘텐츠 미술 기획](../../design/content/09-art-and-audio.md)의 의도다. 실제 외형 수용은 모델·카메라로 별도 검토한다.
판정 범위·발동 시점 → 팀·선택 대상 → 이동·준비 자세 → 지속 상태 → 장식 순으로 읽히게 한다.
색 외에도 장비 형상·경고 모양·팀 표식을 함께 사용한다.

## 4. 실제 모델과 애니메이션의 구현 방식

**현재 코드 확인:** [hero_rig.gd](../../../game/project-e/scripts/presentation/hero_rig.gd)는 8개 GLB를 불러오고 이름이 있는 노드 관절을 움직인다.
대기·보행·기본 공격·Q/W/E/R·피격·사망·부활의 10개 클립을 `AnimationPlayer`에 코드로 구성한다.
관절 보조 회전·의상 동작도 코드에 있으며 전투의 준비·이동·회복 진행에 맞추어 재생·탐색한다.
GLB에 완성된 스킨 애니메이션이 들어 있거나 `Skeleton3D` 본 제작 파이프라인이 완성되었다고 설명하지 않는다.
기술 판정은 [battle 코드](../../../game/project-e/scripts/battle/)가 소유한다. 동작 길이·애니메이션 이벤트가 피해를 확정하지 않는다.

기존 3명 초상은 저장된 WebP, 신규 5명 초상은 같은 GLB를 `SubViewport`에서 렌더한 결과다.
신규 5명의 얼굴·의상 텍스처는 기존 GLB의 내장 이미지를 재사용한다. 모든 영웅이 별도 수작업 텍스처를 가진 것으로 설명하지 않는다.
근거: [hero_portrait.gd](../../../game/project-e/scripts/presentation/hero_portrait.gd), [V8 제작 설명](../../design/28-eight-hero-prototype.md).

## 5. 재제작 입력·도구와 보존할 계약

| 대상 | 실제 제작 입력과 도구 | 상태 |
|---|---|---|
| 기존 3명 모델 | WebP 6개 + [영웅 생성기](../../../tools/build_hero_models.py), NumPy·Pillow | 현재 코드 확인 |
| 신규 5명 모델 | 기존 GLB 텍스처 + [확장 생성기](../../../tools/build_roster_models_v8.py) | 현재 코드 확인 |
| 환경 GLB 11개 | [환경 생성기](../../../tools/art/build_canal_scenery.py), Python 표준 라이브러리 | 현재 코드 확인 |
| 신규 기술 SVG 20개 | [아이콘 생성기](../../../tools/art/build_roster_icons_v8.py), Python 표준 라이브러리 | 현재 코드 확인 |
| Blender/glTF 직접 편집 | 선택적 외부 편집 경로 | 고정 버전·`.blend` 원본은 미확인 |

**기존 검증 기록:** V5 모델 재현은 CPython 3.12.14, NumPy 2.3.5, Pillow 13.0.0, libjpeg-turbo 3.2.0, libwebp 1.6.0에서 수행했다.
WebP에서 시작한 영웅 3개·환경 11개 GLB가 V5 기준과 바이트 단위로 일치했다. 원화를 처음부터 다시 생성하는 검증은 아니었다.
근거: [재현 기록](../../design/verification/2026-11-06-v5-model-reproduction.md).

**후속 제안:** 생성 명령과 의존성은 [코드·자산 인계](../07-code-assets.md)를 따른다. 직접 수정한 GLB를 보존한 뒤 생성기를 실행한다.
`Head`, 몸통·팔·다리, 무기, 팀 표식의 이름·피벗·계층을 유지하고 WebP 변경 뒤 GLB 내장 JPEG도 갱신한다.
Godot import 뒤 F7의 모든 동작과 실제 경기 시점에서 팔·무기·무릎·의상 연결, 발 접지, 경고 가림을 확인한다.
`SVG/GLB/WebP/셰이더/생성 코드`를 원본으로 관리한다. `.godot/` import 캐시는 편집 원본이 아니다.

## 6. VFX와 음향

[skill_vfx.gd](../../../game/project-e/scripts/presentation/skill_vfx.gd)와 [effects_view.gd](../../../game/project-e/scripts/presentation/effects_view.gd)는 조준·선딜·발동·지속·종료를 상태에 연결한다.
경고 형상은 실제 판정·벽·고지·시야 조건을 따르고 다회 공격은 다음 타격의 시간과 범위를 드러내야 한다.
큰 장식, 이동 흔적, 지속 표식이 실제 공격 범위나 숨은 적 위치를 잘못 알려 주지 않게 검토한다.
기술 SVG는 총 32개다. 파일명·SVG 제목·HUD 기술 이름을 함께 변경한다.

| 음향 입력 사건 | 현재 연결 |
|---|---|
| 바스·테르·세라의 시전/기본공격 시작 | `slash.wav` |
| 리오·오린·루메의 시전/기본공격 시작 | `arcane.wav` |
| 네마·무아의 시전/기본공격 시작 | `nature.wav` |
| 조작 영웅 피격 | `hit.wav` |
| 조작 영웅 레벨 상승 | `level.wav` |
| 소모품 회복 시작 | 아이템 데이터에 지정된 기존 cue |

**현재 코드 확인:** [fantasy_audio.gd](../../../game/project-e/scripts/presentation/fantasy_audio.gd)는 조작 영웅만 관측하며 단일 `AudioStreamPlayer`를 사용한다.
동일 관측 프레임의 우선순위는 레벨 상승 → 피격 → 아이템 → 기술 → 기본공격이다. 새 cue는 이전 재생을 멈추고 재생한다.
기본 출력은 Master, `volume_db = -15.0`이며 일시정지에서 소리를 멈춘다. F7 검토실은 음향 검증을 대신하지 않는다.
[음원 설명](../../../game/project-e/assets/audio/README.md)은 5개 합성 원음, 16kHz·16-bit PCM·mono·0.18~0.36초를 기록한다.
**후속 제안:** 영웅별 음색, 단계별 타격음, 죽음·부활 신호, 반복 피로도·음량·설정은 실제 교전에서 검토한다.

## 7. 출처와 사용권 전달

[제3자 고지](../../../THIRD_PARTY_NOTICES.md)는 자체 생성 메시·벡터·합성 음향과 이미지 생성 원화·텍스처의 제작 방식을 기록한다.

배포 때 [폰트 설명](../../../game/project-e/assets/fonts/README.md)과 [OFL 원문](../../../game/project-e/assets/fonts/OFL.txt)을 함께 유지한다.

## 8. 후속 품질 검토의 완료 조건

**후속 제안:** 같은 영웅·같은 거리·같은 전장 구도로 시안과 V9 실제 화면을 나란히 비교하고 차이를 항목별로 기록한다.
먼저 비율·실루엣·재질·지도 구조를 맞추고, 다음으로 이동·준비·타격·회복의 연결과 카메라 움직임을 사람 입력으로 본다.
일반 경기에서 여섯 영웅과 여러 기술이 겹칠 때 팀·피해 범위·표식·구역이 읽히는지 확인한다.
자동 검사 통과, 실제 캡처, Windows 수동 경기, 사용자 품질 수용을 각각 별도 결과로 남긴다.
**미확인:** 상용 수준 애니메이션, 시안 대비 완성도 수용, 사람의 음향 피로도, 대상 GPU 성능. 기존 검증으로 승인되지 않았다.
