# 08. UI·입력·카메라 인수 기획서

기준은 **V9 0.9.0**, 정리 대상 커밋은 `e29c36296abf6d365353401dd0cbee411edc531d`다. 작성일은 2026-11-19다.

**현재 코드 확인**은 소스에서 읽은 구현, **기존 검증 기록**은 이전 실행 기록, **후속 제안**은 다음 작업의 후보, **미확인**은 사람이나 새 환경에서 직접 확인하지 않은 사항이다. 이번 문서 작성에서 게임·렌더·포인터 검사를 실행하지 않았다.

## 목표와 화면 흐름

영웅 선택 → 일반 경기 또는 기술 체험 → 전투 HUD → 성장·상점·도움말 → 결과·재시작으로 이어진다. 플레이어가 생존·기술·성장·전장 정보를 읽는 동안 조작이 다른 화면으로 새지 않아야 한다. F7 연출실은 실제 경기와 상태를 분리해 관찰한다.

사용자가 지적한 **카메라의 부자연스러운 느낌**은 기능 검증과 별도 과제다. V9가 세로 방향과 입력 정합성을 맞춘 사실만으로 추적·드래그·시점 크기의 사람 체감까지 해결됐다고 결론 내리지 않는다.

| 시작 | 선택 영웅에 맞는 시작 버튼 |
| 전투 자원 | HP·보호막·마나·레벨·XP·성장 포인트 |
| 기술 | QWER 이름·비용·해금·재사용, 영웅별 패시브 상태 |

기본 창과 뷰포트는 1280×720이다. 작은 창 대응은 HUD 배치와 포인터 차단을 함께 다룬다. 960×540·1280×720·1366×768의 기존 검사 범위를 새 UI 변경의 출발점으로 사용할 수 있다. [프로젝트 설정](../../../game/project-e/project.godot) · [HUD 소스](../../../game/project-e/scripts/presentation/battle_hud.gd)

## 현재 코드 확인: 조작표

| 입력 | 동작 |
|---|---|
| 우클릭 지면 / 보이는 적 | 이동 / 지정 기본 공격 |
| A → 지면 좌클릭 | 공격 이동 |
| Q·W·E·R → 좌클릭 | 기술 조준 후 확정 |
| Esc | 상점 닫기, 조준 취소, 도움말·성장 닫기, 재개·일시 정지의 현재 상태별 처리 |
| S | 조준·대상·이동 목적지 정리 및 정지 명령 |
| G | 성장 화면 |
| B | 기지까지 지상 경로로 걷기 |
| P / D | 상점 열기 / 선택 소모품 사용 |
| F1 | 도움말 |
| Y | 영웅 추적 ON·OFF 전환 |
| Space | 영웅 위치로 즉시 초점 이동하고 추적 ON |
| 가운데 버튼 드래그 | 자유 카메라 이동 |
| 마우스 휠 | 확대·축소 |
| F6 | 전투→전술→근접 시점 순환 |
| F7 | 통합 연출실 |
| 미니맵 좌클릭 / 우클릭 | 자유 카메라 초점 이동 / 해당 지점으로 영웅 이동 |

Space는 한 프레임 위치만 복귀시키는 입력이 아니다. 이후 영웅 추적을 켠다. B는 즉시 귀환이나 채널링 기술이 아니다. 새 조작 설명에서도 이 차이를 유지한다. [입력 소스](../../../game/project-e/scripts/presentation/battlefield.gd)

## 현재 코드 확인: 플레이 카메라 수치

| 항목 | 구현값 |
|---|---|
| 시작 상태 | 추적 ON, 전투 시점 |
| 투영 / FOV / 피치 | 원근 / 42도 / 55도 |
| 추적 | 매 프레임 `1 − exp(−12 × delta)` 비율로 영웅 위치에 접근 |
| 시점 크기 파라미터 | 전투 30, 전술 50, 근접 18 |
| 휠 | 한 단계 ±2, 범위 16~58 |
| 자유 이동 최대 속도 | 23 m/s |
| 초점 범위 | 표시 가로 −31~31, 세로 −55~55 |
| 바라보는 높이 | 초점의 권한 지면 높이 +0.65 m |
| 가장자리 진입 폭 | `32 × min(창 가로, 창 세로) / 720` px |
| UI 위 허용 폭 | 최외곽 `10 × min(창 가로, 창 세로) / 720` px |
| 드래그 환산 | `크기 / 뷰포트 높이`; 세로 마우스 이동에 1.35 보정 |

위 크기는 원근 카메라 거리 계산에 사용하는 파라미터다. 화면에 항상 정확히 30 m가 보인다는 뜻으로 읽으면 안 된다. 초점 높이에 지형 높이가 반영되며 실제 지면 클릭도 같은 높이 필드를 찾는다. [플레이 카메라](../../../game/project-e/scripts/presentation/playable_battlefield.gd) · [드래그](../../../game/project-e/scripts/presentation/battlefield.gd)

## 현재 코드 확인: 추적과 자유 시점의 전환

1. 경기 시작 때 포인터가 이미 가장자리에 있어도 바로 추적을 해제하지 않는다.
2. 포인터가 화면 내부에 들어왔다가 가장자리로 새로 진입하면 자유 시점으로 전환한다.
3. 가장자리 안쪽에서 바깥쪽으로 속도를 연속 증가시키고 대각선 합성 속도를 제한한다.
4. 기술·공격 이동 조준 중, 모달 UI 중, 창 포커스가 없을 때 가장자리 이동을 멈춘다.
5. 좌클릭을 누른 동안 가장자리 이동을 진행하지 않는다.
6. 창 포커스를 잃으면 드래그와 가장자리 진입 상태를 정리한다.

카메라 입력은 경기 진행·패널·텍스트 입력 포커스 조건을 공유한다. 토스트는 전장 클릭을 막는 모달 패널과 다르게 취급한다. [카메라 상태 소스](../../../game/project-e/scripts/presentation/playable_battlefield.gd)

## 현재 코드 확인: 세로 전장·미니맵·선택

화면 아래가 하단 팀 0, 위가 상단 팀 1이다. 표시 동·북 좌표는 전투 `(x,y)`에서 `(-y,x)`로 변환한다. 카메라, 가장자리 이동, 드래그, 미니맵의 지형·아이콘·안개가 이 기준을 공유한다.

미니맵 지도 내용은 **80:124** 비율을 유지하며 패널 안 여백을 둔다. 여백 클릭은 소비하되 영웅·카메라 명령을 만들지 않는다. 적 구조물의 위치·파괴 상태는 공개하지만 적 현재 HP를 미니맵 정보로 읽지 않는다.

유닛 선택은 화면상 발·몸 높이를 따라 검사하고 구조물 반경은 카메라의 화면 수평축으로 투영한다. 겹친 후보의 선택 우선순위는 영웅→병력→구조물→셀→정령목이다. 고지·경사 지면 클릭은 평평한 `Y=0` 면만 사용하지 않는다. [표시 축](../../../game/project-e/scripts/presentation/battlefield_layout.gd) · [미니맵](../../../game/project-e/scripts/presentation/tactical_map.gd) · [표적 선택](../../../game/project-e/scripts/presentation/battlefield.gd)

## 현재 코드 확인: 패널과 F7 연출실

성장·상점·도움말·일시 정지는 경기 진행과 전장 입력을 함께 막는다. 상점·도움말은 열기 전 정지 상태를 저장해 복원한다. 성장은 일시 정지 메뉴·상점·도움말과 동시에 열지 않으며 닫을 때 진행 상태로 돌아간다. 서로 다른 패널의 복원 구현을 하나의 공통 스택으로 가정하지 않는다.

F7은 원래 경기를 일시 정지하고 별도 플레이 장면에서 영웅 대기·이동·공격·QWER·피격·사망·부활·언덕 이동을 보여준다. 네마 W·R의 정령목, 무아 W·R의 구역 등은 실제 명령으로 준비한다. 연출실 종료 시 원래 장면과 정지 상태를 복원한다.

전체 맵 관찰 모드는 세로 방향을 공유하며 양 핵이 패널 사이에 들어오도록 구도를 조정한다. 영웅별 동작 관찰 구도는 별도다. 연출실의 성장·아이템·피해를 원래 경기 상태에 합치지 않는다. [연출실 소스](../../../game/project-e/scripts/presentation/review_lab.gd)

## 기존 검증 기록: 해결한 부분

2026-11-10 V9 기록에는 실제 카메라 투영·레이, 상하 핵 배치, 좌·중·우 순서, 네 방향 이동·드래그, 미니맵 역변환·안개, 구조물 가장자리 선택 검사가 있다. 기존 화면·포인터 319개 및 세로 전장 렌더 23개 검사를 소스와 배포 PCK에서 확인한 기록이 있다.

이 기록의 화면 검사는 Linux OpenGL 환경이며 Windows EXE는 headless 120프레임 기동까지였다. Windows에서 사람이 전체 경기를 조작하거나 Alt-Tab·GPU별 체감을 확인했다는 근거가 아니다. [V9 검증 기록](../../design/verification/2026-11-10-v9-verification.md)

## 미확인과 후속 제안: 카메라 체감

**미확인:** 세로 전환 이후 사용자가 느끼는 추적 지연, 가장자리 전환, 확대 단계, 고지에서의 초점 이동, 드래그 세로 보정의 적절성은 사람 플레이 결과가 없다.

**후속 제안:** 같은 영웅·같은 경로에서 추적·자유 시점, 평지·경사·고지, 세 시점 크기를 비교한다. 불편 시각, 당시 조준·패널·포커스 상태, Space 재중앙 횟수를 함께 기록한다. 추적 계수 12·속도 23·드래그 보정 1.35를 새 값으로 바로 확정하지 않는다.

## 후속 제안: 작업 완료 판정

- [ ] 작은 창에서도 8명 선택·모드·시작과 모든 주요 패널을 실제 포인터로 누른다.
- [ ] 영웅 키·초상·HUD 이름·QWER가 일치하고 UI 클릭이 전장에 새지 않는다.
- [ ] 네 가장자리·대각선·새 진입·조준·포커스 상실·Space의 상태 전이를 확인한다.
- [ ] 세로 미니맵 여백·정역변환·안개·구조물 가장자리 선택을 확인한다.
- [ ] F7의 8명·32개 액티브와 원래 경기 격리를 확인한다.
- [ ] 카메라 수정 전후 사람 기록을 남기고 조작 정합성과 체감 평가를 구분한다.

위 목록은 다음 변경의 완료 조건이다. 이번에 새로 통과한 검사 목록이 아니다.
