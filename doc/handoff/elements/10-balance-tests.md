# 10. 밸런스·플레이테스트·검증 인수 기획서

기준은 **V9 0.9.0**, 정리 대상 커밋은 `e29c36296abf6d365353401dd0cbee411edc531d`다. 작성일은 2026-11-19다.

- **현재 코드 확인**: 소스·도구·검사 파일의 내용을 읽어 확인했다는 뜻이다.
- **기존 검증 기록**: 저장소에 남은 과거 실행 결과다. 이번에 재실행하지 않았다.
- **후속 제안**: 다음 작업에서 사용할 절차·관측·완료 조건 후보이며 새 기능 확정이 아니다.
- **미확인**: 사람 플레이, 새 환경 실행 또는 이번 범위에서 검증되지 않은 사항이다.

## 목표와 검증 흐름

기능 오류와 체감 문제를 구분하고, 영웅·라인 성장·지원·공성이 실제 핵 파괴까지 이어지는지 확인한다. 수정 후 종료 시간이 줄었다는 사실만으로 밸런스 완료를 선언하지 않는다. 빠른 돌파의 회복·수비 기회와 느린 경기의 피해 공백을 함께 평가한다.

후속 작업 순서는 기술 단독 → 동일 조건 교전 → 병력·셀을 포함한 라인 → 고정 조합 전체 경기 → 사람 조작 관찰이다. 각 단계에서 빌드·편성·관측 상한·입력 조건을 기록한다. 원작 비교는 별도의 관찰 근거와 버전을 명시한다.

## 현재 코드 확인: 재현 명령과 산출물

아래는 저장소 루트에서 실행하는 기존 절차의 예다. **이 문서 작성 중 실행하지 않았다.** 엔진·출력 경로는 새 환경의 실제 절대 경로로 바꾸고 결과 폴더는 실행별로 새로 만든다.

```sh
python tools/check_godot.py --godot /absolute/path/to/Godot_v4.7.2-stable_linux.x86_64

/absolute/path/to/Godot_v4.7.2-stable_linux.x86_64 \
  --headless --path game/project-e --script ../../tools/measure_siege.gd -- \
  --hero=bas --limit=3000 --output=/absolute/new-run-directory \
  --source=YOUR_CHECKOUT_REVISION --label=bas
```

`--hero=orin`·`--hero=tere`로 위 나머지 편성을 고른다. 종료 코드 0은 자연 승패, 1은 관측 상한, 2는 입력·출력 실패다. 기본 전투는 30 Hz, 바깥 관찰 호출은 0.5초, 상태 스냅샷은 5초다. 사건의 피해 시각과 체류 시간의 표본 정밀도를 구분한다.

산출물은 `siege-<label>-summary.json`, `-events.jsonl`, `-samples.jsonl`이다. `--source`는 실행자의 설명 문자열이며 Git 일치 자동 검사가 아니다. 결과에 담긴 실제 전투 파일별 SHA-256과 관찰기 SHA-256을 체크아웃과 대조해야 한다. [관찰기 소스](../../../tools/measure_siege.gd)

## 후속 제안: 사용자 피드백별 관측표

| 질문 | 기록할 값 | 먼저 구분할 원인 |
|---|---|---|
| 미니언 밸런스가 이상한가 | 1 HP 체류, 영웅 마무리 비율, 공성 생존·대상별 피해 | 의도된 유보·표적 선택·실제 수치 |
| 공성이 긴가 | 핵 노출·첫 피해·파괴, 피해 최대 공백, 영웅·병력 동시 체류 | 도착 부족·짧은 병력 생존·회복·표적 전환 |
| 너무 빨리 끝나는가 | 첫 외곽·내곽·핵, 수비 합류·회복·역전 시도 | 초반 압박·재배치·방어 선택 |
| 세로 맵이 읽히는가 | 라인·진영 인지, 지원 결정→합류, 미니맵 클릭 오류 | 표시 방향·동선·클릭 역변환 |
| 카메라가 부자연스러운가 | 불편 시각, 추적·자유 상태, 조준·포커스, Space 횟수 | 추적 지연·전환·드래그·고저차 |
| 영웅 대응이 가능한가 | 핵심 연계 수행, 상대 회피·차단, 마나 부족 시간 | 학습·경고·조건·수치 |

공통 기록에는 커밋·버전·OS·GPU·해상도·입력 장치, 양 팀·라인·진영, 참가자 경험, 시작 모드, 중단 여부를 포함한다. 같은 편성에서 진영을 바꾸고 주요 변수 하나씩 비교한다. 봇 기록과 사람 기록은 실행 조건을 각자 명시한다.

## 미확인과 우선 작업

**미확인:** 사람이 V9를 처음 배워 전체 경기를 수행한 결과, Windows 수동 플레이·Alt-Tab·GPU별 성능, 8명 전체 조합의 사람 밸런스, 원작 정확 거리·평균 경기 시간은 과거 자동 검사로 확정되지 않았다.

**후속 제안:** 먼저 현재 빌드로 수동 재현을 남기고 미니언·공성·카메라의 불편 장면을 특정한다. 자동 검사는 바뀐 계약과 회귀 위험을 확인하는 데 사용하고, 사람 체감을 수치 검사 합계로 대신하지 않는다. 새 목표 시간·카메라 계수·병력 배율은 이 문서에서 확정하지 않는다.

## 후속 제안: 작업 완료 판정

- [ ] 각 결과에 실제 빌드·엔진·조건·로그·출력 해시를 연결한다.
- [ ] 관측 상한과 자연 종료, 중간 정책과 최종 정책을 구분한다.
- [ ] 해당 변경의 규칙 회귀와 필요한 실제 화면·포인터 확인을 완료한다.
- [ ] 공성 변경은 종료 시간 외에 초반 돌파·피해 공백·동반 체류·사망도 비교한다.
- [ ] 미니언·카메라 사용자 피드백은 동일 빌드의 사람 관찰로 재평가한다.
- [ ] 해결·남음·미확인·다음 제안을 분리하고 기존 증거를 덮어쓰지 않는다.

위 목록은 후속 변경의 완료 조건이며 이번에 수행한 테스트 결과가 아니다.
