# 02. 세로 전장·동선·시야 인수 기획서

기준은 **V9 0.9.0**, 정리 대상 커밋은 `e29c36296abf6d365353401dd0cbee411edc531d`다. 작성일은 2026-11-19다.

**현재 코드 확인**은 소스를 읽어 확인한 구현, **기존 검증 기록**은 보존된 이전 실행 결과, **후속 제안**은 다음 작업의 후보, **미확인**은 새 환경 또는 사람 플레이에서 확인하지 않은 사항이다. 이번 문서 작성에서 게임이나 회귀 검사를 실행하지 않았다.

## 목표와 플레이 흐름

M01 수로 공방은 **하단 아군에서 상단 적군으로 전진하는 왼쪽·중앙·오른쪽 세 라인**이다. 라인에 머물며 성장할지, 연결로로 지원할지, 측면 경험치 셀을 확보할지 선택하게 한다. 고지는 경험치 보상과 시야 이점을 주되 올라가고 내려오는 경로를 요구한다.

흐름은 기지 출발 → 라인 합류 → 셀 또는 인접 라인 선택 → 합류·철수 → 구조물 돌파다. 맵 변경은 길의 모양뿐 아니라 실제 합류 시간, 시야, 클릭 가능 지면, 구조물 주변 충돌을 함께 다뤄야 한다.

## 현재 코드 확인: 세 좌표계를 혼동하지 않기

| 용도 | 좌표 정의 | 인수 시 주의 |
|---|---|---|
| 전투 권한 | 2D `(x, y)`; 팀 0에서 팀 1로 가는 축은 `+x` | 거리·충돌·경로·기술은 이 좌표 |
| 표시 동·북 | `(−y, x)` | 아래 표의 위치는 이 좌표 |
| Godot 월드 | `(x, 지면 높이, −y)` | 표시를 위해 월드 지형을 다시 회전하지 않음 |
| 화면 방향 입력 | 화면 가로·아래 축을 표시 좌표로 변환 후 역변환 | 드래그·가장자리 이동·미니맵에 같은 기준 사용 |

`battlefield_layout.gd`의 `to_view()`·`from_view()`가 표시 방향의 기준이다. 카메라는 월드 `−x` 쪽에서 바라본다. 기존 시뮬레이션 좌표를 유지한 것은 V9의 구현 결정이며 원작 내부 좌표계에 대한 주장과 무관하다. [표시 기준 소스](../../../game/project-e/scripts/presentation/battlefield_layout.gd)

| 치수 | 현재 값 |
|---|---|
| 미니맵 표시 범위 | 표시 가로 −40~40 m, 세로 −62~62 m |
| 보행 판정의 바깥 한계 | 시뮬레이션 `abs(x) ≤ 59`, `abs(y) ≤ 39`에서 반경 여유 검사 |
| 라인 / 연결로 / 셀 진입 경사 폭 | 6 / 4 / 3 m |
| 영웅 / 탑 / 핵 충돌 반경 | 0.45 / 1 / 2 m |
| 고지 / 기본 지면 높이 | 2.4 / 0 m |
| 고지 패드 반경 | 2.2 m |
| 경사 높이 보간 시작 기준 | 고지 중심에서 2.0 m |

표시 사각형 전체가 보행 가능한 것은 아니다. 라인·연결로·기지·구조물 발판·셀 발판·경사를 합친 영역에서 벽과 구조물 충돌을 뺀다. 고지 높이는 패드와 경사 높이의 최댓값으로 계산하므로 2.0 m 보간 기준과 2.2 m 패드 경계를 같은 값으로 취급하지 않는다. [지형 권한 소스](../../../game/project-e/scripts/battle/battle_map.gd)

## 현재 코드 확인: 라인과 합류 경로

| 라인 | 표시 좌표 중심 경로 | 중심선 길이 |
|---|---|---:|
| 왼쪽 | `(0,−50) → (−18,−26) → (−18,26) → (0,50)` | 112 m |
| 중앙 | `(0,−50) → (0,50)` | 100 m |
| 오른쪽 | `(0,−50) → (18,−26) → (18,26) → (0,50)` | 112 m |

| 연결로 | 중앙 출입점 → 측면 출입점 |
|---|---|
| 왼쪽 아래 / 위 | `(0,−22) → (−18,−10)` / `(0,22) → (−18,10)` |
| 오른쪽 아래 / 위 | `(0,−22) → (18,−10)` / `(0,22) → (18,10)` |

각 연결로 중심선은 `sqrt(18² + 12²)`로 약 21.63 m다. 이동속도 6 m/s에서 약 3.6초는 **출입점 사이 계산값**이다. 전투 위치에서 출입점까지, 출구에서 지원 대상까지의 시간과 길막은 별도로 더해진다.

현재 경로 직선화와 실제 이동은 최대 0.08 m 간격으로 같은 보행 여유를 검사한다. 좁은 비보행 경계를 직선화가 건너뛰게 만들면 기지 복귀와 공성 합류가 함께 망가질 수 있다. [경로 처리 소스](../../../game/project-e/scripts/battle/battle_map.gd)

## 현재 코드 확인: 구조물과 기지

| 라인 | 하단 내곽 / 외곽 | 상단 외곽 / 내곽 |
|---|---|---|
| 왼쪽 | `(−21.5,−26)` / `(−21.5,−10)` | `(−21.5,10)` / `(−21.5,26)` |
| 중앙 | `(3.5,−30)` / `(3.5,−10)` | `(−3.5,10)` / `(−3.5,30)` |
| 오른쪽 | `(21.5,−26)` / `(21.5,−10)` | `(21.5,10)` / `(21.5,26)` |

하단·상단 핵은 각각 `(0,−50)`, `(0,50)`이다. 부활 기준점은 `(0,−56)`, `(0,56)`이고 영웅별 라인 오프셋이 적용된다. 회복·구매 구역은 표시 가로 −6~6, 하단 세로 −59~−53 또는 상단 53~59다.

탑의 공격 사거리 **8.5 m**, 시야 **12 m**, 구조물의 동반 병력 검사 **12 m**는 목적이 다르다. 맵을 수정할 때 한 반경으로 합치지 않는다. 탑의 사거리 판정에는 공격 대상의 반경도 더해진다. [구조물 생성](../../../game/project-e/scripts/battle/battle_state.gd) · [기지 판정](../../../game/project-e/scripts/battle/battle_consumables.gd)

## 현재 코드 확인: 경험치 셀과 고지

| 위치 | XP 총량 | 지형 |
|---|---:|---|
| 왼쪽 아래 `(−24,−18)` | 40 | 고지 |
| 왼쪽 위 `(−24,18)` | 20 | 일반 발판 |
| 중앙 아래 `(−6,−24)` | 30 | 일반 발판 |
| 중앙 위 `(6,24)` | 30 | 일반 발판 |
| 오른쪽 아래 `(24,−18)` | 20 | 일반 발판 |
| 오른쪽 위 `(24,18)` | 40 | 고지 |

셀은 HP 180, 반경 0.55 m이며 첫 생성 30초, 파괴 후 재생성 45초다. 처치 팀의 살아 있는 영웅 중 14 m 안의 대상이 셀 XP와 골드 10을 나눈다. 여섯 셀의 XP 합계는 180이다. 20·30·40은 팀 전체 자동 지급량이 아니라 해당 셀 한 개의 공유 원보상이다.

왼쪽 아래 고지는 `(−18,−18)`로 라인 복귀하거나 `(−18,−12)`로 지원 경사를 내려간다. 오른쪽 위 고지는 `(18,18)`과 `(18,12)`가 대응 출구다. 두 경로가 있다는 사실은 고정 지형 정보이며 셀의 현재 생존 여부와 구분한다. [셀 생성](../../../game/project-e/scripts/battle/battle_state.gd) · [보상](../../../game/project-e/scripts/battle/battle_rules.gd)

## 현재 코드 확인: 시야와 정보 공개

| 항목 | 규칙 |
|---|---|
| 시야원 | 살아 있는 아군 영웅·병력·탑·핵 |
| 관측 반경 | 병력 8 m, 영웅·탑·핵 12 m |
| 팀 공유 | 아군 시야원 중 하나가 관측하면 공유 |
| 벽 | 모든 시야원의 물리 시선 차단 |
| 고지 | 낮은 영웅·병력은 고지 상단을 밝히지 못함; 고지에서는 아래 관측 가능 |
| 탑·핵 | 높이 제한 없이 자기 반경 안 고지 관측; 벽 검사는 유지 |
| 설치물·셀 | 정령목·물감 구역·닻·셀 자체는 독립 시야원 아님 |
| 고정 정보 | 지형·경사, 구조물 위치·파괴 상태는 공개 정보 |
| 현재 전투 정보 | 적 HP·동적 유닛·셀 생존은 현재 관측 조건에 따름 |

낮은 곳에서 보이지 않는 적을 신규 공격 대상으로 선택할 수 없다. 이미 발사된 탄의 추적·피해와 화면에 정보를 공개하는 조건은 서로 다르므로 두 경계를 함께 확인해야 한다. ## V9 처리 범위와 열린 과제

**현재 코드 확인:** 전장·카메라·미니맵·안개·입력 역변환을 공통 세로 기준에 맞췄다. 지형 연결 관계와 전투 좌표를 다시 설계한 변경은 아니다.

**기존 검증 기록:** 2026-11-10 기록에는 세로 전장 78개 행동 검사와 별도 실제 렌더 23개 검사가 있다. 양 핵의 상하 배치, 라인 순서, 지면 레이, 미니맵 왕복, 안개 정합성, 구조물 가장자리 선택과 960×540 입력을 포함했다. [V9 검증](../../design/verification/2026-11-10-v9-verification.md)

**미확인:** 원작 전장의 정확 거리·구조물 수·평균 이동 시간, 새 환경에서의 체감, 사람 지원 이동의 평균 손익은 확정하지 않았다. 세로 방향 일치가 원작 정밀 복제를 뜻하지 않는다.

**후속 제안:** 동선을 바꿀 때 지원 시작→합류, 비운 라인의 손실, 셀 획득→복귀 시간을 함께 기록한다. 지형 문제와 카메라 조작 문제는 같은 재현 장면에서 각각 관찰하되 원인을 섞지 않는다.

## 후속 제안: 작업 완료 판정

- [ ] 양 기지에서 세 라인과 네 연결로를 왕복하고 핵 옆에서 영웅 두 명이 교차한다.
- [ ] 고지 두 출구의 표시·클릭·보행·시야 경계가 같은 권한 지형을 따른다.
- [ ] 화면·미니맵의 진영·라인 순서, 클릭 정방향·역방향, 안개 텍셀이 일치한다.
- [ ] 미니맵 여백 클릭은 명령을 만들지 않고 적의 숨은 HP·셀 재생성을 공개하지 않는다.
- [ ] 경로 수정 뒤 돌진·넉백·구조물 주변 선택과 기지 복귀 회귀를 다시 확인한다.

위 항목은 다음 작업의 완료 조건이며 이번 실행 결과가 아니다.
