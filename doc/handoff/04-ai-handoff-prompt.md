# 다른 AI에게 전달할 시작 프롬프트

아래 “프로젝트 인계 지시”부터 끝까지 복사해 전달하면 된다. 이 파일만으로 전체 소스나 에셋이 전달되지는 않는다. 저장소 접근 또는 소스 ZIP과 기획 문서 묶음을 함께 제공한다.

## 프로젝트 인계 지시

당신은 독립 PC AOS 게임 **Project E — 아스트라 수로 전장**의 작업을 이어받는다.

### 유지할 목표

시티 오브 템페스트에서 참고한 짧은 스킬 순환, 3라인의 성장·합류 판단, 경기 중 능력치 투자, 병력 동반 공성을 유지한다. 캐릭터·세계관·기술의 세부 조합·아트·UI·음향은 독자적으로 만든다. 목표 플랫폼은 PC이며 Steam 출시를 지향한다. 현재 엔진 선택은 Godot이다.

캐릭터는 약 3등신의 세미 카툰 판타지다. 이전 사용자는 시안 대비 실제 모델·맵 품질, 카메라 움직임, 긴 공성, 미니언 밸런스에 불만을 제기했다. 기술 검증만으로 사용자 만족이 확인됐다고 처리하지 않는다.

2026-11-19의 doc/design/31-subculture-fantasy-hero-art-direction.md는 D 혼합형 서브컬처 판타지 제작안을 추가했다. 인게임 3.0~3.5등신과 선택·키아트 6~7등신을 분리하는 제안이며, 현재 코드·모델의 상태나 최종 승인으로 취급하지 않는다. 새 아트 작업은 이 제안과 실제 모델·관절·기술 계약을 함께 읽는다.

### 현재 구현을 정확히 이해하라

- 선택 가능한 영웅은 바스·리오·네마·오린·테르·무아·세라·루메 8명이다.
- 한 경기는 **사람 1명과 봇 5명의 오프라인 3대3**이다.
- 각 영웅은 패시브 1개와 QWER 4개를 갖는다.
- 화면은 아군 하단·적군 상단이며 라인은 좌·중·우다.
- 내부 전투 좌표와 화면 변환은 구분한다.
- XP는 레벨, 성장 포인트는 능력치와 R 해금, 골드는 회복 소비품 구매에 사용한다.
- 일반 병력은 1 HP 마무리를 유보하며 공성병은 마무리할 수 있다.
- V9 공성 수정은 기지 출발 봇의 열린 라인 최대 2명 합류다.
- 온라인 PvP·Steam 연동·상용 아트 품질·8영웅 균형은 완료로 간주하지 않는다.

### 먼저 할 일

1. 기존 작업 상태와 AGENTS.md 등 실제 작업 지침을 확인하고 사용자의 미커밋 변경을 보존한다.
2. 현재 브랜치·HEAD와 원격 변경을 확인한다. 인계 기준보다 새 변경이 있으면 차이를 먼저 읽고 작업 기준 커밋을 기록한다.
3. doc/handoff/README.md, 01-product-and-decisions.md, 02-status-and-open-work.md, 03-next-actions.md를 읽는다.
4. 담당 요소 문서와 연결된 현행 소스·검증 자료를 대조한다. 과거 계획을 현재 구현으로 덮어쓰지 않는다.
5. 개발 요청인 경우 기준 환경에서 실제 재현을 먼저 하고, 원인과 변경 범위를 정한 뒤 진행한다.
6. 사용자가 이번에 지정한 작업이 있으면 그 범위를 우선한다. 별도 작업 지시가 없으면 새 환경 실행 재현과 미해결 항목 점검부터 시작한다.

### 우선 이어갈 검토

- 실제 Windows 조작에서 카메라·클릭·HUD·Alt-Tab을 확인한다.
- V9의 세로 전장이 원래 요구한 동선과 화면 구성을 충족하는지 실제 캡처로 검토한다.
- 공성·미니언은 핵별 노출→피해→파괴, 공격 공백, 병력 생존을 기록해 조정한다.
- 아트는 시안과 동일한 구도의 실제 모델·장비·모션·전장을 비교한다.
- 이후 8영웅의 연계·상대법·조합, 성장·골드·소모품의 필요성을 점검한다.
- 온라인·Steam은 오프라인 검증과 분리된 후속 개발로 다룬다.

### 반드시 지킬 해석 기준

- V9의 8:06.6 / 18:01.3 / 22:22.7은 기존 고정 편성 6봇 실험 결과다. 사람 평균 경기 시간이나 밸런스 완성의 증거가 아니다.
- 12~18분은 목표 가설이다. 이를 맞추려고 승패를 강제하는 규칙을 임의 추가하지 않는다.
- 실제 경기는 TacticalAI를 주입한다. BattleState의 기본 AI로 계측한 결과를 V9와 직접 비교하지 않는다.
- 원작 영상은 과거 143개 정지 표본을 검토한 기록이다. 이번에 영상 전체를 재생·학습했다고 주장하지 않는다.
- 소스 확인, 기존 검증 기록, 이번 실행, 후속 제안을 구분한다.
- 새로운 수치와 기능은 제안 또는 실험으로 표시하고 선택 근거를 기록한다.
- 보고에는 변경 내용·이유·실제 확인·남은 문제와 파일 경로를 포함한다.

### 문서 갱신

현행 규칙은 doc/design/content/와 캐릭터 시트, 후속 작업의 입구는 doc/handoff/, 실행 증거는 같은 버전의 verification/에 남긴다. docs/의 초기 계획이나 과거 검증 원문을 최신 성공처럼 바꿔 쓰지 않는다. 변경 전후와 실제 테스트 결과를 연결해 다음 담당자가 이어갈 수 있게 한다.
